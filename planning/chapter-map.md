# 초기 목차 지도

이 목차는 승인 전 작업안이다. 역사적 순서가 아니라 독자의 이해를 위한 논리적 순서이며, 각 장은 앞 장에서 남긴 병목이나 질문을 다음 장의 필요성으로 연결해야 한다.

## 제1부: 계산 회로를 조합하다

1. 0과 1을 판단하는 논리 게이트
2. NAND만으로 다른 논리를 만드는 이유
3. 반가산기와 전가산기
4. 여러 비트를 더하는 회로와 올림의 지연
5. 곱셈기는 덧셈을 어떻게 조직하는가
6. 여러 계산 기능을 선택하는 ALU

핵심 전환: 게이트의 조합으로 계산 기능을 만들었지만, 아직 한 번에 적은 수의 계산만 수행한다.

## 제2부: 계산 회로를 복제하고 제어를 공유하다

7. 명령어를 실행하는 하나의 CPU 코어
8. 지연시간과 처리량은 어떻게 다른가
9. 하나의 명령으로 여러 데이터를 계산하는 SIMD
10. 스레드로 표현되는 병렬성, SIMT
11. warp와 wavefront가 함께 움직이는 이유
12. 서로 다른 길로 갈 때 생기는 분기 발산

핵심 전환: 연산기를 복제하고 제어를 공유해 처리량을 높였지만, 모든 작업이 같은 흐름으로 움직이지는 않는다.

## 제3부: GPU라는 계산 공장을 먹여 살리다

13. SM과 CU는 무엇을 묶어 놓은 단위인가
14. 트랜지스터 예산을 어디에 쓸 것인가
15. 연산기가 많은데도 기다리는 이유
16. 레지스터에서 외부 메모리까지: 데이터의 거리
17. 삼각형과 픽셀을 처리하는 그래픽 파이프라인
18. 그래픽 장치가 범용 계산 장치가 되다

핵심 전환: 연산 능력이 늘자 데이터 공급과 이동 비용이 새로운 병목이 된다.

## 제4부: 데이터를 재사용하고 연산을 전용화하다

19. 신경망 계산에서 행렬이 반복되는 이유
20. 연산보다 데이터 이동이 더 비쌀 때
21. 큰 행렬을 작은 타일로 나누는 이유
22. 행렬 곱셈과 누산을 하나의 흐름으로 묶다
23. Tensor Core와 혼합 정밀도의 절충
24. GPU·TPU·NPU와 다음 계산 장치

핵심 결론: 범용성을 일부 줄이고 반복되는 계산과 데이터 흐름을 전용화하면 처리량과 에너지 효율을 높일 수 있지만, 정확도·유연성·프로그래밍 부담이라는 대가를 치른다.

## 구조 검토에서 답해야 할 질문

- CPU 코어를 설명하는 데 필요한 최소 범위는 어디까지인가?
- 그래픽 파이프라인을 제4부로 가는 필수 인과 단계로 만들 수 있는가?
- SIMD와 SIMT를 독자가 구별할 만큼 설명하면서도 회사별 구현의 예외를 과도하게 늘리지 않는가?
- 메모리 계층과 타일링 사이의 연결이 충분히 가깝게 배치되어 있는가?
- Tensor Core 이후의 AI 가속기를 NVIDIA 중심의 결말로 만들지 않는가?
