# 수학적 질문 중심의 4부 20장 목차 지도

상태: 구조 고정 — 4부 20장, 장 순서, 행렬 도입 시점 확정. 세부 원고 검증은 계속 진행

이 책은 GPU의 부품을 순서대로 설명하지 않는다. 1~15장에서는 진리표·이진수·덧셈·합·벡터·픽셀·격자처럼 각 개념에 가장 자연스러운 작은 예제로 계산의 명세·분해·의존성·병렬성·데이터 이동을 설명한다. 행렬 곱셈은 16장에서 처음 완결하며, 앞에서 따로 익힌 개념이 하나의 큰 계산에서 어떻게 만나는지 보여주는 종합 문제로 사용한다.

정확한 산술에서 같은 답을 내더라도 하드웨어에서는 비용이 다를 수 있다. 각 장은 먼저 **계산이 요구하는 양**을 다음 네 칸에 기록한다.

> 연산 횟수 · 의존 단계 · 데이터 이동 · 저장공간

그다음 **기계가 제공하는 자원**을 별도 칸에 기록한다.

> 연산기 수와 처리율 · 쓸 수 있는 시간 단계 · 통로의 대역폭과 거리 · 가까운 저장 용량 · 값 하나의 비트 수

예를 들어 같은 연산 횟수라도 연산기를 더 많이 제공하면 동시에 처리할 수 있는 양이 늘어난다. 연산 횟수와 연산기 수는 같은 종류의 숫자가 아니며, 실제 비용과 성능은 계산의 요구량과 기계 자원이 만나는 지점에서 생긴다.

정밀도는 이 네 비용과 같은 방향의 비용이 아니다. 수의 범위·정밀도·오차는 네 비용을 줄이는 대신 **정답에서 무엇을 내주는가**를 보여 주는 항목으로 따로 기록한다. 서로 다른 단위를 하나의 점수로 합산하지 않는다. `같은 답`은 우선 정확한 정수·실수 산술의 수학적 결과를 뜻하며, 유한 정밀도에서 계산 순서가 결과를 바꾸는 경계는 17~18장에서 명시적으로 다룬다.

회로 면적·전력·제어 복잡성·프로그래밍 난도도 각 장의 설계 대가로 기록한다. 다만 이 값들을 네 계산 비용이나 정밀도와 억지로 한 단위에 합치지 않는다. 이 항목들은 각 장 끝의 「이번 장의 선택과 비용」에서 같은 순서로 되짚는다.

수학적 설명 흐름은 `명세 → 분해 → 의존성 → 재배열 → 재사용 → 근사`, 하드웨어 구현 흐름은 `조합 → 복제 → 공유 → 데이터 재사용 → 전용화`다. 두 흐름은 실제 발명의 역사나 유일한 필연적 진화 경로가 아니다.

## 행렬 곱셈을 사용하는 원칙

- 서장에서는 `2×2` 수치 예제와 결과 한 칸의 계산으로 행렬 곱셈이라는 목적지를 보여주되, 일반 행렬 곱셈 공식·내적·시그마·첨자는 16장까지 미룬다.
- 1~15장에는 행렬을 미리 가르치기 위한 반복 예제를 넣지 않는다. 각 장의 수학적 질문에 가장 짧고 자연스러운 예제를 고른다.
- 16장에서 작은 행렬 곱셈을 처음부터 끝까지 계산한다. 이때 앞 장의 덧셈·합의 의존성·독립 계산·데이터 위치를 명시적으로 회수한다.
- 16~17장은 같은 행렬 예제를 재사용해 새로운 산술 문제를 반복해서 풀게 하지 않는다.
- 20장은 행렬 곱셈을 다시 계산하는 장이 아니라, 이미 계산한 한 예가 어떤 표현과 물리적 제약을 거쳐 GPU·AI 가속기의 설계 선택으로 이어졌는지 회고하는 장이다.

## 서장: 행렬 곱셈 한 줄은 기계에서 어떻게 움직이는가

- 목적: `C = A×B`라는 한 줄을 목적지로 먼저 보여주되, 독자가 행렬을 안다고 가정하지 않는다.
- 핵심 장면: 행렬 곱셈이라는 짧은 수학 표기와 이를 실행하는 거대한 칩의 대비만 보여준다. 결과 한 칸의 계산법은 16장까지 가르치지 않는다.
- 물리적 제약: 연산기 수, 신호와 연산의 0이 아닌 시간, 값이 오가는 거리와 통로의 폭, 가까운 저장공간, 수를 담는 비트 수가 모두 유한하다는 다섯 조건을 소개한다.
- 비용 지도: `계산이 요구하는 양`과 `기계가 제공하는 자원`을 두 열로 나누어 보여준다. 연산 횟수와 연산기 수, 의존 단계와 쓸 수 있는 시간, 이동량과 대역폭·거리, 필요한 저장량과 가까운 용량을 서로 마주 놓는다. 비트 수는 표현 범위·정밀도와 연결하되 `정답에서 내주는 것`으로 따로 기록한다.
- 중심 조건: 정확한 산술에서는 같은 수학적 답을 여러 방법으로 얻을 수 있지만, 유한한 비트에서는 그 동치가 어디까지 보존되는지도 나중에 다시 묻는다고 예고한다.
- 책의 지도: 행렬의 한 칸 → 더 작은 산술 → 이진 덧셈 → 진리표로 내려갔다가, 진리표 → 병렬 실행 → 타일링 → 행렬 가속기로 다시 올라온다. 계산 방법을 가르치지 않고 내려가는 길의 모양만 보여준다.
- 주의: 서장은 진리표를 가르치거나 행렬 계산을 시작하지 않는다. 본문 1장은 실제 진리표에서 출발한다.

## 제1부: 함수를 비트 계산으로 분해하다

### 1장. 가능한 경우를 모두 적으면 함수가 된다

- 수학적 질문: 입력과 출력의 관계를 빠짐없이 어떻게 명세하는가?
- 교육 목표: 일상 규칙표에서 2입력 진리표를 완성하고, 진리표가 물리 부품이 아니라 불 함수(Boolean function)의 명세임을 이해한다.
- 완결 예제: AND 진리표를 만들고 NAND 두 개로 같은 출력을 구현해 네 행을 모두 확인한다.
- NAND 도입 동기: 규칙마다 새 부품을 만드는 대신 한 종류의 단순한 부품을 조합할 수 있다면 무엇을 얻는지 한 문단으로 설명한다.
- 선택과 비용: 입력이 n개면 진리표가 2ⁿ행이 된다는 규모 증가, 게이트 두 개의 조합과 지연.
- 다음 질문: 같은 함수를 만드는 식과 회로가 여러 개라면 무엇을 기준으로 고르는가?

### 2장. 같은 함수를 여러 식으로 분해할 수 있다

- 수학적 질문: 하나의 진리표를 서로 다른 논리식과 회로로 표현할 수 있는가?
- 교육 목표: NAND로 NOT·AND·OR·XOR를 만드는 과정보다, NAND와 NOR가 각각 논리적으로 보편적이라는 말이 무엇을 뜻하고 무엇을 뜻하지 않는지 이해한다.
- 완결 예제: 같은 XOR 진리표를 두 가지 논리식으로 표현하고 필요한 게이트 수와 가장 긴 경로를 비교한다.
- 하드웨어 사례: NAND만으로 구성하는 교육용 추상화와 실제 표준 셀 설계의 차이.
- 선택과 비용: 게이트 수, 회로 깊이, 배선, 한 종류 부품의 단순성.
- 다음 질문: 참과 거짓을 다루는 함수가 어떻게 수를 나타내고 계산하는가?

### 3장. 0과 1을 자릿값으로 읽으면 수가 된다

- 수학적 질문: 같은 비트가 논리값이면서 수의 자릿값이 될 수 있는가?
- 교육 목표: 이진수의 자릿값, 비트 폭과 표현 범위를 이해하고 반가산기·전가산기로 한 자리의 합과 올림을 계산한다.
- 완결 예제: 4비트 덧셈 한 건을 올림까지 끝내고, 2의 보수로 작은 음수와 뺄셈을 설명한다.
- 선택과 비용: 값을 저장·이동하는 비트 수, 표현 가능한 범위, 올림이라는 의존성. 표현 범위는 물리 비용과 구분해 정답의 조건으로 기록한다.
- 다음 질문: 여러 자리의 합은 왜 앞자리 결과를 기다리는가?

### 4장. 같은 덧셈도 마지막 올림을 만드는 길은 다르다

- 수학적 질문: 답과 연산 횟수가 비슷해도 계산의 깊이는 달라질 수 있는가?
- 교육 목표: 올림을 한 자리씩 전달하는 덧셈과 올림 정보를 묶어 미리 계산하는 생각을 비교한다.
- 완결 예제: 4비트 덧셈에서 올림 사슬의 단계 수를 세고, 더 많은 보조 논리를 써서 기다림을 줄이는 사례를 비교한다.
- 하드웨어 사례: 리플 캐리와 빠른 덧셈기의 대표적 아이디어. 특정 구조를 유일한 정답으로 제시하지 않는다.
- 선택과 비용: 연산·게이트 수와 덧셈 한 번 안에서 가장 긴 회로 경로 사이의 절충.
- 다음 질문: 곱셈은 새로운 종류의 마법인가, 익숙한 덧셈의 재배열인가?

### 5장. 곱셈과 여러 계산은 작은 함수의 조합이다

- 수학적 질문: 곱셈과 연산 선택은 이미 만든 함수로 어떻게 분해되는가?
- 교육 목표: 이진 곱셈을 분배법칙에 따른 부분곱과 덧셈으로 완성하고, 멀티플렉서가 여러 함수 중 하나를 고르는 함수임을 이해한다.
- 완결 예제: 작은 이진 곱셈 한 건과 덧셈·뺄셈·AND·OR 중 하나를 고르는 미니 ALU 표를 완성한다.
- 하드웨어 사례: 곱셈기와 산술논리장치(ALU)는 수학적 규칙을 물리적으로 조직하는 여러 방법 중 대표 사례다.
- 선택과 비용: 부분곱 수, 덧셈 깊이, 사용하지 않는 회로의 면적, 선택 제어.
- 다음 질문: 선택 신호 자체도 비트라면 같은 회로가 시간에 따라 다른 계산을 할 수 있는가?

## 제2부: 같은 계산을 다른 순서로 놓다

### 6장. 이전 결과를 다음 계산에 넣으면 시간이 생긴다

- 수학적 질문: `다음 값 = 현재 값에 함수를 적용한 결과`라는 반복을 회로가 어떻게 수행하는가?
- 교육 목표: 조합회로와 순차회로를 구분하고 레지스터·클럭·상태를 점화식과 시간표로 이해한다.
- 완결 예제: `x 다음 = x + 1`을 네 번 반복하며 각 클럭의 입력·출력을 표로 완성한다.
- 하드웨어 사례: 레지스터는 이전 값을 기억하고 클럭은 계산 단계를 나눈다. 상세 플립플롭 회로는 제외한다.
- 선택과 비용: 저장공간, 단계 수, 동기화, 한 회로의 시간적 재사용.
- 다음 질문: 어떤 함수를 적용할지도 비트로 적을 수 있는가?

### 7장. 명령어도 계산을 고르는 비트 묶음이다

- 수학적 질문: 계산 규칙을 회로에 고정하지 않고 데이터처럼 표현할 수 있는가?
- 교육 목표: 작은 명령어가 연산 종류와 레지스터 번호를 담은 비트 묶음이며, 그 일부가 5장의 ALU 선택 신호가 된다는 사실을 이해한다.
- 완결 예제: 4~6비트 교육용 명령어 두세 개를 손으로 해독하고 프로그램 카운터에 따라 순서대로 실행한다.
- 하드웨어 사례: 레지스터, ALU, 간단한 메모리, 제어로 구성한 최소 CPU 코어. 상세 파이프라인·분기 예측·비순차 실행은 제외한다.
- 선택과 비용: 범용성의 이익과 명령 해독·상태 저장·순차 실행의 비용.
- 다음 질문: 계산 하나를 빨리 끝내는 것과 많은 계산을 끝내는 것은 같은가?

### 8장. 여덟 개의 수를 더하는 두 가지 순서

- 수학적 질문: 여러 수의 합을 어느 순서로 묶느냐가 완료 시간을 바꿀 수 있는가?
- 교육 목표: 일렬 합과 나무형 합을 비교해 전체 일의 양과 가장 긴 의존 사슬을 구분한다. 4장의 `덧셈 한 번 안쪽의 회로 경로`와 이번 장의 `여러 덧셈 사이의 의존 사슬`이 서로 다른 층위임을 먼저 밝힌다. 여덟 수에 임시 번호를 붙여 작은 합을 완성한 뒤 시그마 기호 `Σ`가 같은 덧셈을 짧게 적는 표기임을 도입한다.
- 완결 예제: 수 8개의 합을 차례로 더하는 경우와 쌍으로 묶어 더하는 경우의 덧셈 횟수와 단계를 모두 센 뒤, 이미 계산한 합을 `Σ`로 다시 적는다.
- 하드웨어 연결: 지연시간, 처리량, 파이프라인, 복제된 연산기는 서로 다른 비용을 바꾼다.
- 선택과 비용: 요구량에는 연산 횟수(work)와 가장 긴 의존 사슬(span), 자원에는 동시에 쓴 연산기 수를 기록한다.
- 다음 질문: 서로 의존하지 않는 계산을 같은 시각에 실행해도 답은 변하지 않는가?

### 9장. 서로 번호가 다른 계산은 언제 동시에 할 수 있는가

- 수학적 질문: 같은 함수를 서로 다른 데이터에 적용하는 계산들은 언제 독립적인가?
- 교육 목표: 8장에서 합을 적기 위해 잠깐 사용한 번호와 아래 첨자를 벡터의 각 원소를 가리키는 일반 표기로 확장한다. 스칼라 계산을 각 원소에 적용하고 결과 번호 사이에 의존성이 없을 때 병렬로 배열할 수 있음을 이해한다.
- 완결 예제: 두 벡터의 원소별 합을 한 개 연산기로 순서대로 계산하는 경우와 네 실행 레인으로 계산하는 경우를 비교한다.
- 하드웨어 사례: SIMD는 여러 데이터에 같은 명령을 적용해 제어를 공유한다.
- 선택과 비용: 요구량에는 같은 총 연산량과 줄어든 의존 단계, 자원에는 늘어난 실행 레인과 공유한 제어를 기록한다.
- 다음 질문: 실행 폭이 달라지거나 일부 데이터가 다른 규칙을 선택하거나 메모리를 기다리면 어떻게 하는가?

### 10장. 같은 식 안에서 서로 다른 길을 고를 때

- 수학적 질문: 조각별 함수(piecewise function)를 여러 데이터에 함께 적용하면 어떤 계산이 낭비되는가?
- 교육 목표: 독립 스레드처럼 표현한 계산을 하드웨어에서 묶어 실행하는 SIMT와 분기 발산을 이해한다.
- 완결 예제: 네 입력 중 한 개는 `x/2`, 세 개는 `x+20`을 계산하는 예에서 교육용 경로 길이를 각각 3단계와 2단계로 정하고 활성 레인 비율을 끝까지 센다. 이 단계 수는 특정 명령의 실제 지연시간이 아니라 분기 발산만 분리해 보기 위한 가정임을 표 앞에 밝힌다.
- 하드웨어 사례: NVIDIA warp와 AMD wavefront는 일반 원리의 서로 다른 사례다. 실행 폭 독립성, 많은 스레드 묶음을 준비해 대기를 숨기는 아이디어를 소개하고 상세 스케줄링은 다음 부로 넘긴다.
- 선택과 비용: 공유한 제어, 비활성 레인, 준비된 작업 수, 분기와 메모리 대기.
- 다음 질문: 실제로 같은 함수를 수백만 번 적용해야 하는 문제는 어디에서 나타났는가?

## 제3부: 많은 계산을 어디에 배치하고 데이터를 어떻게 옮길 것인가

11~12장은 반복 계산을 고정 기능과 프로그램 가능한 경로, 유한한 실행 자원에 어떻게 배치할지 묻는다. 13~15장은 계산에 필요한 값을 어디에 두고 어떤 순서로 옮겨야 연산기를 먹여 살릴 수 있는지 묻는다.

### 11장. 어떤 계산을 고정하고 어떤 계산을 바꿀 수 있게 둘까

- 수학적 질문: 반복되는 계산을 회로에 고정할 때와 프로그램으로 바꿀 수 있게 둘 때 무엇을 얻고 잃는가?
- 교육 목표: 정점·삼각형·픽셀마다 반복되는 계산을 통해 고정 기능과 프로그램 가능 기능의 절충을 이해한다. 그래픽과 딥러닝은 목적이 달랐지만 많은 데이터에 비슷한 수치 연산을 반복한다는 계산의 모양이 겹쳤고, 프로그래머블 GPU와 GPGPU 생태계가 이 재사용을 가능하게 했음을 역사와 논리로 나누어 설명한다.
- 완결 예제: 같은 픽셀 규칙을 고정된 한 함수와 바꿀 수 있는 두 함수로 처리할 때 제어·범용성·낭비를 비교한다. 이어서 그래픽의 픽셀 8개와 신경망의 중간값 8개에 서로 다른 수치 규칙을 반복 적용하는 작은 작업표를 나란히 놓고, 식은 다르지만 독립된 항목 수·반복 규칙·공유 제어라는 선택과 비용의 구조가 겹칠 수 있음을 센다. 행렬 곱셈은 도입하지 않는다.
- 하드웨어 사례: 고정 기능 중심 대표 세대, 프로그래머블 셰이더, CUDA와 GPGPU, 2012년 대규모 CNN의 GPU 학습을 시간 순서로 구분한다. 연표는 특정 회사 자료로 확인한 대표 이정표이지 보편적인 최초 발명 연표가 아님을 밝힌다. 초기 GPU를 행렬 곱셈 전용 장치로 설명하지 않는다.
- 선택과 비용: 반복 계산 수, 고정 기능의 효율, 프로그램 가능성에 필요한 제어·상태 비용.
- 다음 질문: 계산 대상이 실제 연산기보다 훨씬 많으면 어떻게 나누어 실행하는가?

### 12장. 유한한 연산기에 무수한 계산을 배치하다

- 수학적 질문: 수많은 독립 계산을 제한된 연산기와 시간 단계에 어떻게 배정하는가?
- 교육 목표: 작업을 실행 묶음과 블록으로 나누고 준비된 묶음을 번갈아 실행해 대기 시간을 숨기는 원리를 이해한다.
- 완결 예제: 16개 독립 계산을 4개 실행 레인에 네 차례 배치하고, 일부 계산이 기다릴 때 다른 묶음을 선택하는 시간표를 완성한다.
- 하드웨어 사례: 스케줄러·레지스터·연산기·로컬 저장공간을 묶은 일반 실행 블록 뒤에 NVIDIA SM과 AMD CU를 사례로 붙인다.
- 가지 않은 길: 복잡한 제어로 단일 작업 지연을 줄이는 설계와 단순한 제어로 많은 작업 처리량을 높이는 설계를 연속적인 설계 공간으로 비교한다.
- 선택과 비용: 연산기·레지스터·저장공간·제어에 쓰는 면적과 전력, 동시 실행 수.
- 다음 질문: 연산기가 준비돼 있어도 필요한 값이 도착하지 않으면 무엇이 병목인가?

### 13장. 같은 수도 어디에 있느냐에 따라 비용이 다르다

- 수학적 질문: 값의 수학적 의미가 같아도 저장 위치가 계산 비용을 바꾸는가?
- 교육 목표: 레지스터, 가까운 공유 저장공간, 캐시, 외부 메모리를 거리·용량·공유 범위의 절충으로 이해한다.
- 완결 예제: 같은 네 값을 매번 먼 메모리에서 읽는 경우와 한 번 가까이 두고 반복 사용하는 경우의 이동 횟수를 센다.
- 하드웨어 사례: CUDA shared memory, AMD LDS 같은 명칭은 일반적인 소프트웨어 관리 로컬 저장공간의 사례로 구분한다.
- 선택과 비용: 이동 거리, 이동 횟수, 저장 용량, 동기화, 대역폭과 지연시간.
- 다음 질문: 수학식은 같은데 계산 순서를 바꾸면 데이터 이동도 달라지는가?

### 14장. 같은 식도 계산 순서에 따라 데이터를 다르게 움직인다

- 수학적 질문: 결합법칙과 분배법칙이 허용하는 계산 순서 가운데 어떤 순서가 값을 가까이 재사용하는가?
- 교육 목표: 작은 격자 계산에서 행 우선·열 우선 순서를 비교하고 같은 입력을 다시 읽는 간격을 센다. 9장에서 배운 한 개짜리 아래 첨자를 두 개의 방문 번호로 확장한다.
- 완결 예제: 중첩된 두 방문 번호의 순서를 바꾸어 정확 산술의 결과는 같지만 가까운 저장공간의 재사용이 달라지는 표를 완성한다.
- 주의: 정수의 정확한 연산과 유한 정밀도 부동소수점에서 계산 순서 변경이 갖는 차이는 18장에서 회수한다.
- 선택과 비용: 같은 연산 횟수, 다른 이동 횟수와 접근 규칙성.
- 다음 질문: 연산량과 데이터 이동량의 균형을 하나의 숫자로 비교할 수 있는가?

### 15장. 한 번 가져온 값으로 몇 번 계산하는가

- 수학적 질문: 계산이 연산기에 막히는지 데이터 공급에 막히는지 어떻게 구분하는가?
- 교육 목표: 산술 집약도를 `산술 연산 횟수 ÷ 정한 경계를 통과한 바이트 수`로 이해한다. 같은 크기의 값만 비교하는 교육 예제에서는 먼저 `연산 횟수 ÷ 입력값 읽기 수`를 세고, 결과 쓰기는 별도 열에 기록한 뒤 바이트 단위로 확장한다.
- 완결 예제: 원소별 벡터 합과 작은 격자 계산의 연산 수·입력 읽기 수·결과 쓰기 수를 같은 규약으로 비교한다. 행렬 곱셈 계산은 다음 장까지 미룬다.
- 주의: 수치표로 병목 방향을 먼저 이해한 뒤 roofline 그림을 소개한다. roofline은 상한 모형이지 실제 실행 시간을 정확히 예측하는 공식이 아니다.
- 선택과 비용: 연산량, 이동량, 최대 연산 처리량, 최대 메모리 대역폭.
- 다음 질문: 행렬 곱셈은 왜 같은 값을 여러 번 쓸 기회가 특히 많은가?

## 제4부: 행렬의 반복을 재사용하고 전용화하다

### 16장. 행렬의 한 칸은 곱셈과 합이다

- 수학적 질문: 행렬 곱셈의 모든 결과는 어떤 작은 계산의 반복인가?
- 교육 목표: 4×4 예제의 `Cᵢⱼ = Σₖ₌₀³ AᵢₖBₖⱼ`에서 기호와 범위를 하나씩 정의하고, 결과 한 칸이 내적이며 여러 결과 칸이 어느 첨자에서 독립인지 이해한다. 일반 크기의 범위 표기는 예제 뒤에 분리한다.
- 완결 예제: 작은 행렬 곱셈의 모든 원소를 계산하고 각 A·B 원소가 몇 번 사용되는지 센다.
- 병렬성 연결: 결과 첨자 i와 j의 독립성, k 방향 합의 의존성을 8~10장의 개념으로 회수한다.
- 선택과 비용: 곱셈·덧셈 수, 합의 깊이, 입력값의 이론적 재사용 횟수.
- 다음 질문: 이론적으로 여러 번 쓸 수 있는 값을 작은 가까운 저장공간에서 실제로 어떻게 재사용하는가?

### 17장. 큰 행렬을 블록으로 보아도 같은 행렬이다

- 수학적 질문: 행렬을 작은 블록으로 나눈 뒤 블록끼리 곱해도 왜 같은 답이 나오는가?
- 교육 목표: 블록 행렬 곱셈이 원래 식의 결합·분배법칙을 이용한 재배열임을 이해하고 타일링과 연결한다.
- 완결 예제: 16장에서 완결한 4×4 행렬과 16개 결과를 다시 풀지 않고 가져와 2×2 타일로 나눈 뒤, 네 결과 타일의 블록 계산을 모두 완성한다.
- 데이터 이동 연결: 교육용 무캐시 기준선에서 산술 연산 112회(곱셈 64회와 덧셈 48회)는 그대로이고 입력 읽기가 128회에서 64회로 줄어드는 이유를 밝힌다. 입력용 가까운 저장공간에는 A 타일 하나와 B 타일 하나를 두고, 누적 중인 C 결과 타일은 별도 결과 저장공간에 완성될 때까지 보존한다는 조건을 명시한다. 공통인 최종 결과 쓰기 16회는 별도 기록한다. 48회 모형은 A 타일 두 개와 B 타일 하나를 입력용으로 두고 C 결과 타일 하나를 별도 누산 공간에서 차례로 완성하는 더 큰 자원을 전제로 한다.
- 정확성 조건: 블록화는 `k` 방향 합을 재결합한다. 이 정수 예제에서는 정확히 같은 답이지만 유한 정밀도에서는 반올림 차이가 생기며, 값의 크기 차이와 상쇄에 따라 차이가 마지막 비트보다 커질 수도 있음을 다음 장과 연결한다.
- 선택과 비용: 같은 산술 연산량, 줄어든 먼 메모리 읽기, 늘어난 로컬 저장공간과 동기화.
- 다음 질문: 계산 순서를 바꾸어도 항상 정확히 같은 수가 나오는가?

### 18장. 유한한 비트에는 모든 실수가 들어가지 않는다

- 수학적 질문: 무한히 많은 실수 값을 유한한 비트로 표현하면 무엇을 보존하고 무엇을 잃는가?
- 교육 목표: 부동소수점의 부호·범위·정밀도를 직관적으로 이해하고 FP32·FP16·BF16을 서로 다른 배분 선택으로 비교한다.
- 완결 예제: 작은 십진수를 제한된 자릿수로 반올림해 더하는 순서에 따라 결과가 달라지는 사례와 낮은 정밀도 곱셈·높은 정밀도 누산 사례를 계산한다.
- 주의: 결합법칙이 실수 수학에서는 성립하지만 유한 정밀도 계산에서는 반올림 때문에 그대로 보존되지 않을 수 있음을 구분한다.
- 선택과 비용: 네 물리 비용과 별도로 표현 범위·유효 정밀도·오차를 `정답에서 내주는 것`으로 기록한다. 낮은 정밀도가 값 하나의 바이트 수를 줄여 데이터 이동량도 줄일 수 있지만 실제 속도 향상은 하드웨어 지원과 병목에 달렸음을 밝힌다.
- 다음 질문: 같은 모양의 행렬 곱셈·누산을 계속 반복한다면 그 데이터 흐름을 회로에 직접 새길 수 있는가?

### 19장. 반복되는 행렬 패턴을 하나의 흐름으로 묶다

- 수학적 질문: 곱셈과 누산이 반복되는 이중선형 구조를 범용 명령 여러 개가 아니라 하나의 데이터 흐름으로 만들면 무엇이 달라지는가?
- 교육 목표: 첫째, 반복되는 곱셈-누산을 전용 데이터 경로에 고정하면 범용 명령의 제어 비용과 메모리 접근당 계산량이 어떻게 달라지는지 이해한다. 둘째, 그 구현 방법 가운데 입력과 부분합을 처리 요소 사이로 규칙적으로 흐르게 하는 systolic 데이터 흐름을 별도의 특정 계열로 배운다.
- 완결 예제: 작은 systolic MAC 배열에서 입력과 부분합이 시간 단계마다 이동하는 표를 완성한다. 이 예를 모든 행렬 연산 장치의 내부 구조로 일반화하지 않는다.
- 하드웨어 사례: NVIDIA Tensor Core, AMD MFMA, Intel XMX, Google TPU MXU는 장 끝의 선택 사례 표로만 비교한다. 각 사례에는 공개 자료로 확인된 연산 종류·입력과 누산 형식·지원 모양만 쓰며, 내부 데이터 흐름이 확인되지 않은 칸은 비워 둔다. TPU MXU의 공개 systolic 설명을 다른 장치에 투사하지 않는다.
- 선택과 비용: 처리량과 에너지 효율의 이익, 지원 모양·정밀도·데이터 배치·범용성의 제약.
- 다음 질문: 같은 행렬 계산이라도 왜 GPU, TPU, NPU가 서로 다른 답을 내놓는가?

### 20장. 하나의 행렬 곱셈이 진리표에서 가속기까지 가는 길

- 수학적 질문: 같은 행렬 곱셈을 서로 다른 제약 아래 구현하면 어떤 설계 선택이 달라지는가?
- 교육 목표: 한 행렬 곱셈을 진리표, 덧셈기, 곱셈기, 합의 깊이, 병렬 첨자, 메모리 이동, 타일링, 정밀도, 전용화의 순서로 다시 추적한다.
- 비교 틀: 장치 전체가 아니라 **실행 자원 또는 데이터 경로**를 `지원하는 계산 범위가 얼마나 좁은가`라는 연속 축 위에 놓고 범용성·데이터 흐름·저장공간·정밀도·소프트웨어 생태계를 비교한다. 하나의 CPU나 GPU도 범용 경로, 벡터 경로, 행렬 경로, 고정 기능 경로처럼 축 위의 여러 점을 함께 가질 수 있다고 밝힌다.
- 용어 주의: ASIC은 같은 층위의 한 장치명이 아니라 특정 목적용 집적회로라는 넓은 범주이며 TPU도 그 사례다. NPU는 표준 내부 구조의 이름이 아니다. 모든 GPU·AI 작업이 행렬 곱셈으로 환원된다고 쓰지 않는다.
- 결론: 수학은 답을 정하지만 답에 도달하는 물리적 비용까지 하나로 정하지 않는다. 서로 다른 제약은 서로 다른 계산 구조를 낳는다.
- 열린 끝: 칩 밖의 메모리와 연결망이 다음 병목이 되지만 분산 학습·데이터센터 운영은 본서 범위에서 제외한다.

## 구조 고정 후에도 계속 검증할 질문

- 서장이 행렬을 가르치지 않고 목적지와 지도를 보여주는 역할에 머무는가?
- 1장이 실제 진리표에서 시작하며 2장은 반복이 아니라 함수 분해의 비용을 설명하는가?
- 3~5장에서 덧셈·곱셈·ALU가 부품 목록이 아니라 수학적 분해로 읽히는가?
- 6~7장이 CPU 교재로 팽창하지 않고 시간적 반복과 명령 비트의 역할만 하는가?
- 4장의 회로 경로와 8장의 의존 사슬이 서로 다른 층위로 구분되는가?
- 9~10장에서 SIMD와 SIMT의 차이가 회사 용어 암기가 아니라 독립성·조각별 함수·대기 문제로 설명되는가?
- 11장의 그래픽 역사가 수학적 반복 계산의 사례라는 범위를 넘지 않는가?
- 12장에서 CPU와 GPU를 이분법으로 만들지 않고 가지 않은 설계 선택을 보여주는가?
- 13~15장의 데이터 위치·순서·산술 집약도가 16~17장의 행렬 재사용으로 직접 이어지는가?
- 18장의 유한 정밀도가 전공 수치해석 장으로 과도하게 팽창하지 않는가?
- 12~13장과 19~20장의 일반 원리가 제조사 문서가 아니라 벤더 중립 학술자료로도 뒷받침되는가?
- 1~15장에 행렬 예제를 억지로 반복하지 않으면서 16장이 앞 개념의 종합으로 읽히는가?
- 각 장에서 연산 횟수·의존 단계·이동·저장공간 중 최소 하나를 실제 숫자로 세고, 정밀도는 별도 층으로 기록하는가?
