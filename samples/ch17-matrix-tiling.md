# 샘플 3 — 17장: 큰 행렬을 블록으로 보아도 같은 행렬이다

상태: 설명 방식 검증용 초안

## 계산을 줄이지 않고도 빨라질 수 있을까

행렬을 작은 조각으로 나눠도 지난 장에서 센 산술 연산은 사라지지 않는다. 그런데도 타일링이 성능을 높일 수 있는 이유는 **데이터를 멀리서 가져오는 횟수**를 줄일 수 있기 때문이다. 이 장에서는 계산을 덜 하는 방법이 아니라 같은 계산을 다른 순서로 놓는 방법을 살펴본다.

## 지난 장의 계산을 다시 풀지 않는다

지난 장에서 다음 두 행렬의 곱을 16개 결과 칸까지 모두 계산했다.

```text
A = 1  2  0  1        B = 1  0  2  1
    0  1  3  0            0  1  1  0
    2  0  1  1            1  1  0  2
    1  1  0  2            2  0  1  1
```

그때 얻은 결과와 연산 횟수는 다음과 같았다.

```text
C = A×B = 3  2  5  2
          3  4  1  6
          5  1  5  5
          5  1  5  3
```

> 곱셈 64번 + 덧셈 48번 = 산술 연산 112번

이 장에서는 16개의 원소별 계산을 다시 반복하지 않는다. 이미 완결한 같은 예제를 2×2 타일로 재배열해도 결과와 산술 연산량이 유지되는지 확인하고, 달라지는 입력 읽기 수만 새로 센다.

## 행렬을 네 개의 타일로 나눈다

A와 B를 각각 2×2 블록 네 개로 나눈다.

이것은 행렬을 다른 계산으로 바꾸는 일이 아니다. 원래 식에 들어 있던 곱셈과 덧셈을 결합법칙과 분배법칙이 허용하는 범위에서 작은 블록끼리 묶어 적는 것이다. 아래의 블록 계산이 앞에서 구한 16개 원소와 같아지는지를 직접 확인하면 그 사실을 검증할 수 있다.

```text
A00 = 1 2    A01 = 0 1    B00 = 1 0    B01 = 2 1
      0 1          3 0          0 1          1 0

A10 = 2 0    A11 = 1 1    B10 = 1 1    B11 = 0 2
      1 1          0 2          2 0          1 1
```

결과 C도 C00, C01, C10, C11이라는 네 타일로 나뉜다. 각 결과 타일에는 두 번의 작은 행렬 곱셈이 더해진다.

### 왼쪽 위 타일

```text
C00 = A00×B00 + A01×B10

A00×B00 = 1 2    A01×B10 = 2 0
           0 1                 3 3

C00 = 3 2
      3 4
```

예를 들어 A01×B10의 왼쪽 위 값은 `0×1 + 1×2 = 2`이고, 오른쪽 아래 값은 `3×1 + 0×0 = 3`이다.

### 오른쪽 위 타일

```text
C01 = A00×B01 + A01×B11

A00×B01 = 4 1    A01×B11 = 1 1
           1 0                 0 6

C01 = 5 2
      1 6
```

### 왼쪽 아래 타일

```text
C10 = A10×B00 + A11×B10

A10×B00 = 2 0    A11×B10 = 3 1
           1 1                 4 0

C10 = 5 1
      5 1
```

### 오른쪽 아래 타일

```text
C11 = A10×B01 + A11×B11

A10×B01 = 4 2    A11×B11 = 1 3
           3 1                 2 2

C11 = 5 5
      5 3
```

네 타일을 다시 붙이면 앞에서 구한 C와 같은 결과가 나온다. 이 정수 예제에서는 타일링이 계산의 답도, 필요한 64번의 곱셈과 48번의 덧셈도 바꾸지 않았다.

블록 계산에서도 덧셈 48번이 어디에 있는지 확인할 수 있다.

- 2×2 타일 곱 하나에는 결과 네 칸마다 덧셈 1번이 있으므로 덧셈 4번이 필요하다.
- 타일 곱은 모두 8번이므로 그 안의 덧셈은 `4×8=32번`이다.
- 각 결과 타일에서 두 부분 결과의 네 칸을 합치는 덧셈은 `4×4=16번`이다.
- 전체 덧셈은 `32+16=48번`이다.

정확히 말하면 블록 계산은 네 곱을 더하는 순서를 `k` 방향의 두 덩어리로 다시 묶는다. 정수의 정확한 덧셈에서는 묶는 순서를 바꿔도 답이 같다. 그러나 유한한 비트로 소수를 근사하면 중간 반올림 때문에 결과가 달라질 수 있다. 대개 낮은 자리에서 갈리지만 값의 크기 차이와 상쇄에 따라 더 큰 차이가 날 수도 있다. 이것은 `같은 수학식`과 `같은 기계 결과`의 경계를 보여주는 문제이며, 다음 장에서 차이가 생기는 이유를 센다.

## 달라진 것은 읽기 횟수다

지난 장에서 가장 단순하고 비효율적인 교육용 기준선을 128회로 세었다. 캐시는 없고, 결과 원소 하나를 계산할 때마다 필요한 A의 네 값과 B의 네 값을 외부 메모리에서 새로 읽으며, 다른 결과를 계산할 때는 이전 값을 전혀 재사용하지 않는 모형이다.

저장 슬롯까지 비교하기 위해 기준선의 실행 순서를 더 명확히 정하자. A와 B의 값 한 쌍을 두 입력 슬롯으로 가져와 곱하고, 결과 하나의 부분합 한 개를 별도 누산 슬롯에 유지한다. 네 쌍을 차례로 읽고 결과 하나가 완성되면 한 번만 외부에 쓴다. 따라서 입력 슬롯은 2개, 누산 슬롯은 1개면 되지만 입력 재사용은 없다. 여기서 슬롯은 이 교육 일정에서 동시에 보존하는 값의 수이지 실제 GPU 레지스터의 물리적 개수를 뜻하지 않는다.

- 결과 원소 하나당 외부 읽기: A 4개 + B 4개 = 8개
- 결과 원소 수: 16개
- 전체 외부 읽기: 8 × 16 = 128개 값

이번에는 2×2 타일 하나씩 계산한다. 입력을 위한 가까운 저장공간에는 A 타일 하나와 B 타일 하나, 즉 값 여덟 개만 동시에 들어간다고 하자. 이와 별도로 누적 중인 C 결과 타일의 네 부분합을 둘 누산 공간이 있다. C 결과 타일 하나가 완성될 때까지 그 네 부분합을 유지하고, 완성된 네 값만 외부 메모리에 한 번씩 쓴다. 한 번의 입력 타일 곱셈이 끝나면 A·B 입력 타일은 다음 두 타일을 넣기 위해 비운다. 이 조건에서 각 입력값은 한 번의 타일 곱셈 안에서 두 번 재사용된다.

수학적으로는 A와 B의 각 값이 전체 4×4 곱셈에서 네 번씩 쓰인다. 그러나 A 타일 하나와 B 타일 하나만 들어가는 가까운 저장공간에서는 그 네 번의 기회를 한꺼번에 모두 살리지 못하고, 두 번씩 나누어 재사용한다. 그래서 입력 32개를 정확히 한 번씩만 읽는 이상적인 32회가 아니라 64회가 된다.

- 한 타일 곱셈에 읽는 값: A 타일 4개 + B 타일 4개 = 8개
- 결과 타일 하나에는 타일 곱셈 2번이 필요함: 8 × 2 = 16개
- 결과 타일 수: 4개
- 전체 외부 읽기: 16 × 4 = 64개 값

이 단순 모형에서는 외부 읽기가 128개에서 64개로 절반이 된다. 곱셈 64번과 덧셈 48번은 그대로다. 가까운 저장공간에 올린 값을 두 번씩 사용했기 때문에 멀리 있는 메모리까지 다녀오는 횟수만 줄었다.

앞 장의 교육용 규약으로 세어 보자. 분자에는 곱셈 64회와 덧셈 48회를 합친 산술 연산 112회를 넣고, 분모에는 같은 크기의 입력값을 읽은 횟수를 넣는다. 모든 방법에서 부분합은 결과가 완성될 때까지 누산 공간에 유지하므로 최종 결과 쓰기 16회는 별도 열에 표시한다.

- 결과 원소마다 새로 읽기: 112 ÷ 128 = 0.875 연산/입력값 읽기
- 2×2 타일에서 재사용: 112 ÷ 64 = 1.75 연산/입력값 읽기

분자인 산술 연산량은 그대로이고 분모인 입력 읽기가 절반이므로, **입력 읽기만 분모로 센 이 교육 모형**의 산술 집약도는 두 배다. 실제 roofline 분석에서는 `연산 횟수 ÷ 정한 메모리 경계를 통과한 바이트 수`를 사용하므로 값의 크기와 읽기·쓰기를 어디까지 포함했는지 함께 밝혀야 한다.

가까운 입력 저장공간이 조금 더 커지면 또 다른 답이 가능하다. A 타일 두 개와 B 타일 하나, 값 열두 개를 동시에 둘 수 있다고 하자. 별도 누산 공간에는 앞 모형과 마찬가지로 C 결과 타일 하나의 네 부분합을 둔다. A00과 A01을 남겨 둔 채 C00을 완성해 쓰고 이어서 C01을 완성해 쓰면, 첫 두 결과 타일에 필요한 읽기는 A 타일 8개와 B 타일 16개, 합계 24개다. 두 결과 타일을 동시에 보존할 필요는 없다. 아래쪽 두 결과 타일도 같은 방식으로 24개를 읽으므로 전체는 48개가 된다.

> (A 타일 8개 + B 타일 16개) × 결과 타일 행 2개 = 입력 읽기 48개

이 모형의 교육용 집약도는 `112÷48≈2.33 연산/입력값 읽기`다.

| 방법 | 곱셈 | 덧셈 | 입력 읽기 | 결과 쓰기 | 입력 슬롯 | 누산 슬롯 | 연산/입력 읽기 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 결과 원소마다 쌍을 새로 읽기 | 64 | 48 | 128 | 16 | 2 | 1 | 0.875 |
| 2×2 타일: A 1개·B 1개 | 64 | 48 | 64 | 16 | 8 | 4 | 1.75 |
| 2×2 타일: A 2개·B 1개 | 64 | 48 | 48 | 16 | 12 | 4 | 약 2.33 |

따라서 `64`는 타일 크기만으로 정해지는 보편적인 답이 아니다. 입력 저장공간의 용량, 결과 부분합을 보존할 누산 공간, 타일을 처리하는 순서를 함께 정했을 때 나오는 답이다.

이 숫자는 타일링의 원리를 보여주는 교육용 모형이다. 실제 GPU에는 캐시가 있으므로 순진한 방법도 모든 값을 항상 외부 메모리에서 다시 읽는 것은 아니다. 반대로 타일링에는 타일을 옮기는 명령, 동기화, 주소 계산, 가장자리 처리 비용이 든다. 실제 읽기 수와 성능 향상은 캐시 상태, 데이터 배치, 타일 크기와 하드웨어에 따라 달라진다.

## 타일은 클수록 좋은가

타일을 크게 만들면 한 번 가져온 값을 더 많이 재사용할 가능성이 커진다. 하지만 가까운 저장공간은 작다. 큰 타일은 더 많은 공유 메모리나 레지스터를 차지하고, 그 결과 한 실행 블록에 동시에 머물 수 있는 스레드 묶음이 줄 수 있다. 레지스터가 부족하면 값이 오히려 더 먼 메모리로 밀려날 수도 있다.

따라서 타일 크기는 다음 비용을 함께 맞추는 선택이다.

- 큰 타일의 이익: 데이터 재사용 증가, 외부 메모리 접근 감소
- 큰 타일의 비용: 저장공간 증가, 동시 실행 수 감소 가능성, 가장자리 낭비
- 작은 타일의 이익: 적은 저장공간, 더 유연한 배치
- 작은 타일의 비용: 같은 데이터를 더 자주 가져올 가능성

타일링은 “행렬을 작게 자르는 요령”이 아니라 제한된 가까운 저장공간으로 데이터 재사용을 실현하는 방법이다. 여기서 책의 네 번째 동사인 **데이터 재사용**이 하드웨어 구조와 직접 연결된다.

## 이번 장의 계산 장부

| 구분 | 기록 |
|---|---|
| 보존한 기능·정확한 결과 | 행렬 곱셈의 16개 답, 곱셈 64회, 덧셈 48회 |
| 계산이 요구하는 양 | 입력 읽기 128→64→48회, 결과 쓰기 16회 |
| 기계가 제공할 자원 | 입력 슬롯 2→8→12개, 누산 슬롯 1→4→4개라는 교육용 일정 |
| 유한 정밀도에서 달라질 수 있는 것 | 합을 재결합하면 반올림 결과가 달라질 수 있고 상쇄에 따라 차이가 커질 수 있음 |
| 설계 대가 | 더 많은 가까운 저장공간·주소 계산·동기화를 사용해 먼 입력 읽기를 줄임 |
| 아직 해결되지 않은 제약 | 제한된 비트가 수의 범위·정밀도와 재결합 결과를 어떻게 바꾸는가 |

다음 장에서는 수를 제한된 비트로 근사할 때 생기는 범위·정밀도·반올림의 대가를 살펴본다.
