# 샘플 4 — 16장: 행렬의 한 칸은 곱셈과 합이다

상태: 제4부 진입과 앞 장 개념 회수 검증용 초안

## 지금까지 배운 계산이 한곳에 모인다

행렬은 이 장에서 처음 제대로 계산한다. 앞 장에서 행렬 예제를 미리 반복하지 않은 이유는 행렬 계산에 필요한 생각을 더 작은 문제에서 먼저 익히기 위해서였다.

- 한 계산을 작은 계산으로 나누는 법
- 여러 수의 합에서 전체 연산 횟수와 의존 사슬을 구분하는 법
- 번호가 다른 결과들이 서로 독립인지 확인하는 법
- 같은 값을 여러 번 읽을 때 데이터 위치가 비용을 바꾼다는 사실

이제 이 네 생각을 한 계산에서 만나게 해 보자. 행렬은 숫자를 직사각형 표로 배열한 것이다. 행렬 곱셈은 그 표의 숫자를 아무렇게나 모두 곱하는 규칙이 아니다. 왼쪽 행렬의 **행**과 오른쪽 행렬의 **열**을 짝지어 곱하고 더하는 규칙이다. 짝을 빠짐없이 지으려면 왼쪽 행렬의 가로 길이와 오른쪽 행렬의 세로 길이가 같아야 한다. 이 책의 예제에서는 두 길이가 모두 4다.

## 결과 한 칸부터 계산한다

다음 두 4×4 행렬 A와 B를 곱한다. `4×4`는 가로와 세로에 숫자가 각각 네 개 있다는 뜻이다.

```text
A = 1  2  0  1        B = 1  0  2  1
    0  1  3  0            0  1  1  0
    2  0  1  1            1  1  0  2
    1  1  0  2            2  0  1  1
```

결과 행렬을 C라고 하자. C의 왼쪽 위 칸은 A의 첫째 행과 B의 첫째 열로 만든다.

```text
A의 첫째 행: 1  2  0  1
B의 첫째 열: 1  0  1  2
```

같은 자리에 있는 수끼리 곱한 뒤 네 곱을 더한다.

> 1×1 + 2×0 + 0×1 + 1×2 = 1 + 0 + 0 + 2 = 3

따라서 C의 왼쪽 위 칸은 3이다. 이 한 칸에 곱셈 4번과 덧셈 3번이 들어 있다.

오른쪽으로 한 칸 이동하면 A의 행은 그대로 두고 B의 열만 둘째 열로 바꾼다.

> 1×0 + 2×1 + 0×1 + 1×0 = 0 + 2 + 0 + 0 = 2

행이 바뀌면 A에서 고르는 줄이 바뀌고, 열이 바뀌면 B에서 고르는 줄이 바뀐다. 이것이 행렬 곱셈의 전부다.

## 아래 첨자는 어느 행과 열인지 알려준다

C의 각 칸에 이름을 붙여 보자. `Cᵢⱼ`에서 첫째 번호 `i`는 C의 행, 둘째 번호 `j`는 C의 열을 뜻한다. 이 책에서는 첫 행과 첫 열의 번호를 0으로 시작하므로 왼쪽 위 칸은 `C₀₀`, 그 오른쪽은 `C₀₁`이다.

곱해서 더할 때 안쪽에서 움직이는 번호를 `k`라고 하자. `C₀₀`을 계산할 때 k는 0, 1, 2, 3으로 변하며 A의 첫째 행과 B의 첫째 열을 함께 훑는다.

> C₀₀ = A₀₀B₀₀ + A₀₁B₁₀ + A₀₂B₂₀ + A₀₃B₃₀

8장에서 여러 수의 합을 짧게 적기 위해 배운 시그마 기호 `Σ`를 쓰면 같은 규칙을 다음처럼 쓸 수 있다.

> Cᵢⱼ = Σₖ₌₀³ AᵢₖBₖⱼ

기호부터 외울 필요는 없다. 이 한 줄은 다음 문장을 짧게 적은 것이다.

> C의 i행 j열을 구하려면, k를 차례로 바꾸면서 A의 i행 값과 B의 j열 값을 곱해 모두 더한다.

## 첫째 행을 끝까지 계산한다

같은 A의 첫째 행을 유지하고 B의 셋째·넷째 열을 차례로 고르면 다음 두 값이 나온다.

> C₀₂ = 1×2 + 2×1 + 0×0 + 1×1 = 2 + 2 + 0 + 1 = 5

> C₀₃ = 1×1 + 2×0 + 0×2 + 1×1 = 1 + 0 + 0 + 1 = 2

따라서 C의 첫째 행은 `3, 2, 5, 2`다. 나머지 세 행도 같은 규칙으로 계산하면 다음 결과가 나온다. 모든 행의 계산 과정은 장 끝의 검산 표에 남겨 둔다.

16개 답을 제자리에 놓으면 다음 행렬이 된다.

```text
C = A×B = 3  2  5  2
          3  4  1  6
          5  1  5  5
          5  1  5  3
```

## 어느 계산은 독립이고 어느 계산은 기다려야 하는가

`C₀₀`과 `C₀₁`은 같은 A의 첫째 행을 사용하지만 서로의 답을 기다릴 필요는 없다. `C₀₀`을 계산하지 않아도 `C₀₁`을 계산할 수 있다. 일반적으로 i와 j가 가리키는 16개 결과 칸은 서로 독립이다.

반면 결과 한 칸 안에서는 네 곱을 하나의 합으로 모아야 한다. 네 곱을 차례로 더하는 순서를 선택하면 덧셈 3번의 의존 사슬이 생긴다. 덧셈기를 더 마련하는 것만으로 이 순서가 바뀌지는 않는다. 계산 순서를 나무형으로 바꾸고 여러 덧셈기를 함께 쓸 수 있다면 네 곱을 두 쌍으로 먼저 더한 뒤 두 중간값을 마지막에 더해 의존 단계를 2단계로 줄일 수 있다. 정확한 정수 산술에서는 두 순서가 같은 답을 낸다.

여기서 8장의 두 층이 되돌아온다.

- 전체 일의 양: 결과 하나당 곱셈 4번과 덧셈 3번
- 결과 하나 안의 의존 사슬: 일렬 합이면 덧셈 3단계, 나무형 합이면 2단계
- 서로 독립인 일: 결과 칸 16개
- 필요한 기계 자원: 몇 개의 결과와 몇 개의 곱·합을 동시에 처리할지에 따라 달라짐

회로 하나 안에서 신호가 통과하는 게이트 경로는 4장에서 다룬 층위다. 여기서 세는 것은 이미 하나의 연산으로 보기로 한 곱셈과 덧셈들이 서로 기다리는 **계산 의존 단계**다. 둘을 같은 시간으로 섞어 세지 않는다.

## 전체 연산 횟수를 센다

4×4 결과에는 칸이 16개 있다. 각 칸에 곱셈 4번과 덧셈 3번이 필요하다.

> 곱셈: 결과 16개 × 4번 = 64번

> 덧셈: 결과 16개 × 3번 = 48번

> 산술 연산 합계: 64 + 48 = 112번

이 숫자는 특정 GPU의 명령어 수나 실행 시간을 뜻하지 않는다. 정확한 정수 결과를 이 직접적인 방법으로 만들 때 필요한 산술 연산의 수다. 한 명령이 여러 연산을 처리할 수도 있고, 여러 연산기가 동시에 일할 수도 있다.

## 같은 입력값은 여러 결과에서 다시 쓰인다

A의 왼쪽 위 값 `A₀₀=1`을 따라가 보자. 이 값은 C의 첫째 행에 있는 `C₀₀`, `C₀₁`, `C₀₂`, `C₀₃`을 계산할 때 각각 한 번씩, 모두 네 번 쓰인다. B의 왼쪽 위 값 `B₀₀=1`도 C의 첫째 열에 있는 네 결과에서 모두 네 번 쓰인다.

4×4 행렬에서는 A와 B의 각 입력값이 이론적으로 네 번씩 사용된다. 하지만 수학식에 네 번 나타난다는 사실만으로 기계가 그 값을 가까운 곳에 한 번만 가져온다는 보장은 없다. 결과 칸을 계산할 때마다 멀리 있는 메모리에서 다시 읽는다면 재사용의 기회를 놓친다.

재사용 기회를 하나도 살리지 않는 기준선도 세어 보자. 결과 한 칸을 계산할 때마다 A의 네 값과 B의 네 값을 멀리서 새로 읽는다면 결과당 입력 읽기는 8회다.

> 결과 16개 × 입력 읽기 8회 = 입력 읽기 128회

15장의 교육용 규약으로는 `112÷128=0.875 연산/입력값 읽기`다. 이 숫자는 캐시가 없고 다른 결과 사이에 입력을 전혀 보존하지 않는 기준선이다. 다음 장에서는 같은 행렬을 작은 블록으로 묶어 계산 순서를 바꾸고, 제한된 가까운 저장공간으로 이 128회를 줄인다.

## 검산 표: 나머지 열두 칸

이 표는 독자에게 열두 문제를 숙제로 떠넘기기 위한 것이 아니다. 같은 규칙이 모든 행과 열에 빠짐없이 적용되어 결과가 완결된다는 것을 본문 안에서 확인하기 위한 기록이다. 원리를 이해했다면 모든 줄을 다시 손으로 풀 필요는 없다.

| 결과 | 계산 과정 | 답 |
|---|---|---:|
| C₁₀ | 0×1 + 1×0 + 3×1 + 0×2 | 3 |
| C₁₁ | 0×0 + 1×1 + 3×1 + 0×0 | 4 |
| C₁₂ | 0×2 + 1×1 + 3×0 + 0×1 | 1 |
| C₁₃ | 0×1 + 1×0 + 3×2 + 0×1 | 6 |
| C₂₀ | 2×1 + 0×0 + 1×1 + 1×2 | 5 |
| C₂₁ | 2×0 + 0×1 + 1×1 + 1×0 | 1 |
| C₂₂ | 2×2 + 0×1 + 1×0 + 1×1 | 5 |
| C₂₃ | 2×1 + 0×0 + 1×2 + 1×1 | 5 |
| C₃₀ | 1×1 + 1×0 + 0×1 + 2×2 | 5 |
| C₃₁ | 1×0 + 1×1 + 0×1 + 2×0 | 1 |
| C₃₂ | 1×2 + 1×1 + 0×0 + 2×1 | 5 |
| C₃₃ | 1×1 + 1×0 + 0×2 + 2×1 | 3 |

## 이번 장의 선택과 비용

| 구분 | 기록 |
|---|---|
| 보존한 기능·정확한 결과 | C의 16개 결과와 행렬 곱셈 규칙 |
| 계산이 요구하는 양 | 곱셈 64번, 덧셈 48번, 결과별 합의 의존 단계, 입력값마다 네 번의 사용 기회, 무재사용 기준 입력 읽기 128회 |
| 기계가 제공할 자원 | 동시에 처리할 결과 칸 수와 곱셈기·덧셈기 수, 가까운 저장공간은 아직 정하지 않음 |
| 설계 대가 | 더 많은 결과와 나무형 합을 동시에 처리하려면 더 많은 연산기와 연결이 필요함 |
| 아직 해결되지 않은 제약 | 반복해 쓰는 입력값을 어디에 보존해 128회 읽기를 줄이는가 |
