# Claude 독립 검토 요청: 서장·1~5장 흑백 도해 시안

당신은 일반 대중을 위한 수학·디지털 계산·GPU 교양서의 독립적인 기술 검토자이자 출판 도해 편집자다. 아래에 지정한 현재 파일만 읽고 평가하라. `reviews/` 아래의 과거 리뷰와 프롬프트는 이 요청 파일 외에는 읽거나 인용하지 말라. 프로젝트 파일은 수정하지 않는다.

## 이번 검토의 목적

서장·1~5장 상세 설계에 따라 만든 흑백 SVG 도해 12종이 **초고 집필에 사용해도 될 만큼 기술적으로 정확하고, 일반 독자에게 명료하며, 흑백 인쇄와 축소 조판에 견딜 수 있는지** 판정한다.

목차·제목·장 구성을 다시 설계하는 검토가 아니다. 도해의 문제를 구체적으로 찾되, 문제가 없으면 억지로 지적을 만들지 않는다.

## 확정되어 있어 재심사하지 않을 사항

- 한국어 본제는 『진리표에서 GPU까지』다.
- 전체는 4부 20장이고, 서장과 제1부는 서장·1~5장이다.
- 본문 1장은 진리표에서 시작한다.
- 서장의 `C=A×B`는 목적지 표시이며 행렬 계산법을 가르치지 않는다.
- 1~5장에서는 행렬을 계산하지 않는다.
- 제1부의 장별 필수 도해는 2개씩이며, 이번 시안은 서장 2개와 1~5장 각 2개로 총 12개다.
- 도해는 특정 제품의 물리 구조가 아니라 교육용 추상 모형이다.
- 흑백 인쇄를 전제로 하며 색을 추가하라는 제안은 하지 않는다.
- 비전공 독자 시험은 현재 작업 범위에서 제외했다. 이번 리뷰에서 별도 독자 시험을 필수 조건으로 되살리지 않는다.
- 부제는 미확정이지만 이번 리뷰에서 후보를 선정하지 않는다.

## 시각 검토 방법

- SVG 소스만 읽고 추정하지 말고, 각 SVG를 `/tmp` 아래 PNG로 렌더링해 실제 결과를 직접 확인한다.
- macOS에서는 다음 형태의 읽기 전용 변환을 사용할 수 있다: `sips -s format png <svg> --out <temporary-png>`.
- 임시 PNG 외에는 파일을 만들거나 수정하지 않는다.
- 전체 구도와 축소 가독성을 모두 확인한다. 필요하면 렌더링 크기를 달리해 비교한다.

## 반드시 독립 재검산할 사항

### 서장

- 도해 1이 수학식과 연산기·통로·가까운 저장공간·비트 수를 분리하는가?
- 도해 2가 내려가는 길과 올라오는 길을 역사 연표처럼 보이지 않게 분리하는가?
- 올라오는 길에 명세, 조합, 시간적 재사용, 복제·공유와 GPU, 데이터 재사용, 전용화가 모두 있는가?
- `GPU`가 제목의 구체적 목적지로 보이되 GPU가 유일한 필연적 종착점처럼 보이지 않는가?

### 1장

- AND 진리표가 `0,0,0,1`인가?
- NAND 두 개로 AND를 되찾는 구현이 연결상 맞는가?
- NAND 게이트 2개와 최장 2층이 그림에서 재현되는가?
- 실제 안전회로가 아닌 교육 모형이라는 경계가 보이는가?

### 2장

- XOR 출력이 `0,1,1,0`인가?
- 방법 A가 NAND 6개·최장 4층, 방법 B가 NAND 4개·최장 3층인가?
- 각 사각형을 게이트 하나로 셌을 때 실제 상자 수와 표기가 일치하는가?
- 두 회로의 배선이 설계표의 중간값 관계를 빠짐없이 전달하는가?
- `같은 것`과 `달라진 것`이 실제 칩 성능의 단정으로 확대되지 않는가?

### 3장

- `1000₂`이 무부호 8과 4비트 2의 보수 -8로 갈라지는가?
- 자릿값 8·4·2·1과 비트열 1·0·0·0의 대응이 맞는가?
- `0101+0011=1000`의 네 전가산기 입력·출력과 carry `c1=1,c2=1,c3=1,c4=0`가 맞는가?
- 4장 전까지는 값의 연결만 보여주고 시간 화살표를 넣지 않는다는 원칙을 지키는가?

### 4장

- `1111+0001=1 0000`에서 `g0=1`, `p1=p2=p3=1`, `c1=c2=c3=c4=1`이 맞는가?
- 4장 도해 1이 한 덧셈기 내부 경로와 여러 연산 사이의 알고리즘 의존 단계를 구분하는가?
- 리플 c4 도해에 p·g 게이트 8개와 carry 게이트 8개가 있어 합계 16개인가?
- 리플의 선택한 최장 경로가 p·g 1층과 네 carry cell의 AND·OR 8층을 합쳐 9층인가?
- 펼친 c4 도해에 p·g 8개, 추가 AND 10개, OR 4개가 있어 합계 22개인가?
- 회색으로 표시한 펼친 식 경로가 실제로 1→2→3→4→5→6층을 거쳐 c4에 도달하는가?
- `U0=T0 OR T1`, `U1=T2 OR T3`, `U2=U0 OR U1`, `c4=U2 OR T4`라는 고정 연결과 모순되지 않는가?
- 16 대 22가 완성 덧셈기 전체가 아니라 c4 회로 비교라는 범위가 충분히 보이는가?

### 5장

- 4×4 교차점이 16개이며 각 교차점의 비트 곱이 맞는가?
- `1011₂×1101₂`의 부분곱 행 `11,0,44,88`과 자리 이동 표현이 맞는가?
- 합 `10001111₂=143`, 행 4개, 행 덧셈 3번, 출력 최대 8비트가 맞는가?
- ALU 후보의 AND `0001`, OR `0111`, ADD `1000`, SUB `0010`이 맞는가?
- `op=10`이 ADD를 선택하는가?
- 선택되지 않은 후보를 흐리게 표시해도 흑백에서 선택 상태를 구분할 수 있는가?

## 시각·편집 검토 기준

- 글자나 선, 화살표가 잘리거나 겹치지 않는가?
- 선이 상자를 통과하거나 연결 관계를 잘못 암시하지 않는가?
- 숫자의 아래 첨자, 장 번호, 수식 기호가 렌더링에서 깨지지 않는가?
- 제목, 소제목, 본문, 주석의 위계가 12개 도해에서 일관적인가?
- 회색 명암에만 의존하지 않고 테두리 굵기·점선·라벨로 의미를 함께 전달하는가?
- 본문 폭에 맞게 축소했을 때 작은 글자와 복잡한 회로가 읽힐 가능성이 있는가?
- 도해 하나가 한 가지 중심 메시지를 전달하는가?
- 도해 명세에 없는 장식이나 새로운 선수지식을 추가하지 않았는가?
- 교육용 추상 모형을 실제 칩 구조로 오해하게 하는 요소가 없는가?
- 한국어 문장과 용어가 기준 문서와 일치하는가?

## 출력 형식

- 한국어로 작성한다.
- 8,000자 이내로 쓴다.
- 먼저 12개 도해의 독립 재검산 결과를 도해별 한 줄 표로 제시한다.
- 계산·회로 오류와 시각·편집 문제를 구분한다.
- 문제마다 다음 형식을 지킨다.
  - 위치 또는 검토 대상
  - 문제의 내용
  - 중요도: 높음 / 중간 / 낮음
  - 범주: 1 기술적 오류 / 2 설명상의 문제 / 3 시각·조판 문제 / 4 표현 개선
  - 문제가 되는 이유
  - 구체적인 수정안
  - 수정하지 않을 경우의 위험
- 문체 취향을 기술적 오류로 분류하지 않는다.
- SVG 제작 방식 자체보다 독자가 보게 될 결과를 우선 평가한다.
- 문제가 없는 도해에는 억지로 지적을 만들지 않는다.
- 마지막에 다음을 명시한다.
  1. 판정: 원고 집필에 사용 가능 / 수정 후 사용 가능 / 도해 재설계 필요
  2. 원고 집필 전에 반드시 수정할 항목
  3. 초고 집필과 병행해도 되는 개선
  4. 현재 상태로 유지할 도해와 선택
- 프로젝트 파일을 수정하지 말고 리뷰만 출력한다.
