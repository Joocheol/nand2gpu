# Claude 독립 검토 요청: 8·11·16·17장 연결 샘플

당신은 일반 대중을 위한 수학·디지털 계산·GPU 교양서의 독립적인 기술 검토자이자 출판 편집자다. 아래에 지정한 현재 파일만 읽고 평가하라. `reviews/` 아래의 과거 리뷰와 프롬프트는 읽거나 인용하지 말라. 파일은 수정하지 않는다.

## 확정된 편집 방향

- 본제는 **『진리표에서 GPU까지』**로 확정되어 있다.
- 이 책은 컴퓨터 부품 목록이 아니라, 수학적으로 같은 답도 계산의 분해·의존성·병렬성·데이터 이동·정밀도에 따라 왜 다른 물리적 비용을 갖는지 쉬운 수학으로 설명한다.
- 1~15장에는 행렬 예제를 반복하지 않는다. 16장에서 처음 완결된 행렬 곱셈을 계산한다. 이 선택 자체를 결함으로 지적하지 말고 실제 연결이 성립하는지 평가한다.
- 8장에서 작은 합을 먼저 완성한 뒤 시그마 `Σ`를 도입한다.
- 11장은 그래픽 GPU → 프로그래머블 셰이더 → GPGPU → 딥러닝 GPU 학습의 연결을 다룬다. 그래픽과 AI를 같은 계산·같은 구조로 일반화하거나 순수한 우연·필연으로 단정하지 않는다.
- 16장은 첫 행렬 곱셈과 앞 개념의 종합, 17장은 같은 예제의 블록화와 데이터 이동을 맡는다. 17장에서 16개 원소 계산을 반복하지 않는다.
- 계산 요구량과 기계가 제공하는 자원은 별도 장부다. 정밀도·오차도 별도 정답 장부다.

## 집중 검토 항목

### 1. 8장: 합·work/span·시그마

- `3,1,4,1,5,9,2,6`의 일렬 합과 나무형 합 계산이 모두 맞는가?
- 덧셈 횟수 7, 일렬 스팬 7, 나무형 스팬 3, 최대 덧셈기 4라는 비교가 명시한 추상화 아래 정확한가?
- 4장의 덧셈기 내부 회로 경로와 8장의 여러 덧셈 사이 의존 사슬을 명확히 구분하는가?
- 아래 첨자와 `Σ`를 9장보다 먼저 제한적으로 도입하는 방식이 일반 독자에게 자연스러운가?
- `Σ`가 실행 순서를 정하지 않는 명세 표기라는 설명이 정확하고 교육적으로 효과적인가?

### 2. 11장: 그래픽 GPU에서 AI로 이어지는 전환

- 픽셀 8개의 `y=2x+10` 결과와 연산 횟수, AI 중간값 8개의 `max(0,x)` 결과가 맞는가?
- 고정 기능과 프로그램 가능한 실행 경로의 절충이 과장 없이 설명되는가?
- 게임을 익숙한 사례로 쓰되 GPU의 기원을 게임 하나로 축소하지 않는가?
- 고정 기능 그래픽 → 프로그래머블 셰이더 → 딥러닝 이전 GPGPU → CUDA 같은 범용 환경 → 2012 AlexNet이라는 설명이 사실 범위와 교육적 순서를 지키는가?
- 그래픽과 AI의 `계산 배치 모양 일부가 겹친다`는 주장을 작은 두 예제가 실제로 뒷받침하는가? 원소별 `max` 예제가 GPU의 딥러닝 부상을 설명하는 증거처럼 과대 해석될 위험은 없는가?
- 프로그래밍 환경·라이브러리·생태계의 역할이 하드웨어 결정론을 충분히 피하는가?
- `인류사적 우연`을 해석적 표현으로 제한한 문장이 정확하면서도 독자에게 매력적인가?
- 출처 대장이 각 역사 주장과 제품 한정 사실을 충분히 뒷받침하는가?

### 3. 16장: 첫 행렬 곱셈과 종합

- 4×4 행렬의 16개 원소가 모두 맞는가?
- 곱셈 64, 덧셈 48, 합계 112가 정확한가?
- 각 입력 원소가 네 결과에서 쓰인다는 재사용 횟수가 맞는가?
- 결과 i·j 방향의 독립성과 k 방향 합의 의존성이 정확한가?
- 일렬 합의 덧셈 스팬 3과 나무형 합의 스팬 2가 제품 지연시간이 아니라 연산 의존 단계라는 조건 아래 맞는가?
- 8장의 `Σ`와 work/span, 9장의 독립성, 13~15장의 데이터 위치 질문을 실제로 회수하는가?
- 첫 행렬 장에서 16행 계산표가 완결성에 기여하는지, 아니면 일반 독자에게 불필요한 반복이 되는지 판단하라. 삭제만 제안하지 말고 유지·축약·도해 전환의 장단점을 비교하라.

### 4. 16→17장: 반복 제거와 타일링 모형

- 17장이 16장의 원소 계산을 불필요하게 반복하지 않고 새로운 질문으로 전환하는가?
- 2×2 블록 계산의 네 결과 타일과 최종 결과가 모두 맞는가?
- 블록화가 정확 정수 산술에서는 같은 답과 64회 곱셈·48회 덧셈을 유지하지만 부동소수점에서는 재결합 때문에 마지막 비트가 달라질 수 있다는 설명이 정확한가?
- 기준선 128회 입력 읽기, 입력 타일 8개+결과 부분합 4개의 64회 모형, 입력 타일 12개+결과 부분합 4개의 48회 모형을 각각 직접 재현하라.
- 특히 48회 모형에서 A 타일 두 개를 유지한 채 C00을 완성해 쓰고 C01을 차례로 완성하면 C 결과 타일 하나의 부분합만 유지해도 되는지 검산하라.
- 결과 쓰기 16회를 공통으로 두기 위한 부분합 보존 가정이 충분히 명시됐는가?
- 교육용 `연산/입력값 읽기`와 표준 roofline의 `연산/바이트`가 분명히 구분되는가?

### 5. 네 장의 연결과 목차 고정 가능성

- 8→9→10→11의 흐름이 합의 의존성 → 독립 계산 → 분기 → 실제 대량 계산과 프로그램 가능성으로 이어지는가?
- 11장에서 16장까지 행렬 계산을 미루면서도 GPU와 AI의 연결이 끊기지 않는가?
- 16→17장이 `계산 규칙 → 독립성·의존성 → 이론적 재사용 → 실제 데이터 이동 감소`로 자연스럽게 이어지는가?
- 네 샘플을 기준으로 현재 목차를 구조적으로 고정해도 되는지, 아니면 반드시 먼저 고쳐야 할 연결 결함이 있는지 판단하라.

## 출력 형식

- 한국어로 작성한다.
- 8,000자 이내로 쓴다.
- 먼저 모든 숫자를 직접 재검산한 결과를 짧게 제시한다.
- 문제마다 다음 형식을 지킨다.
  - 위치 또는 검토 대상
  - 문제의 내용
  - 중요도: 높음 / 중간 / 낮음
  - 범주: 1 기술적 오류 / 2 설명상의 문제 / 3 구조·시장성·차별성 / 4 표현 개선
  - 문제가 되는 이유
  - 구체적인 수정안
  - 수정하지 않을 경우의 위험
- 문제가 아닌 확정 방향을 억지로 결함으로 만들지 않는다.
- 문체 취향을 기술적 오류로 분류하지 않는다.
- 마지막에 다음을 쓴다.
  1. 판정: 승인 / 조건부 승인 / 재설계 필요
  2. 목차 구조 고정 가능 여부: 가능 / 수정 후 가능 / 불가
  3. 원고 집필 전에 반드시 수정할 항목
  4. 현재 상태로 유지할 선택
- 파일을 수정하지 말고 리뷰만 출력한다.
