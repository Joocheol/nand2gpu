# Claude 목차·샘플 독립 리뷰

- 검토일: 2026-08-26
- 실행 환경: Claude Code 2.1.228
- 모델: Claude Opus, high effort
- 권한: 프로젝트 파일 읽기만 허용, 수정 권한 없음
- 검토 대상: 프로젝트 허브, 결정 기록, 4부 20장 목차, 로드맵, 검토 기준, 출처 관리대장, 세 샘플
- 기록 방식: Claude 응답의 반복을 줄인 편집 요약본. 아래 판정과 지적은 Claude의 의견이며 자동 승인된 수정 사항이 아니다.

## 전체 판정

**조건부 승인**

Claude는 구조의 골격과 세 샘플의 기술적 신뢰도가 재설계를 요구할 수준은 아니라고 판정했다. 다만 목차를 고정하기 전에 인과 공백, 그래픽 장 배치, 19장 과부하, 핵심 장의 벤더 중립 출처 부족을 처리해야 한다고 보았다.

## 가장 중요한 장점

1. 18장 샘플의 C 행렬 16개 원소, 8개 타일 곱셈, 128→64 읽기 모형을 모두 검산했으며 오류가 없다고 판정했다.
2. 1장의 `진리표는 부품이 아니다`라는 구분이 명세와 구현을 정확히 분리해 확정 본제의 약속을 이행한다고 보았다.
3. 일반 원리와 warp·wavefront 같은 회사별 용어를 구분하는 규칙이 목차, 검토 기준, 출처 대장, 샘플에 반복 적용된 점을 실질적 차별점으로 평가했다.

## 우선순위가 높은 지적사항

### H-1. 1장 샘플과 2장의 역할이 중복된다

- 위치 또는 검토 대상: 1장 샘플, 목차 1~2장
- 문제의 내용: 1장 샘플이 NAND 두 개로 AND를 합성하고 NAND(N,N)=NOT까지 보여줘 2장의 교육 목표 중 상당 부분을 선점한다.
- 중요도: 높음
- 범주: 3. 책의 구조·시장성·차별성에 영향을 주는 문제
- 문제가 되는 이유: 각 장이 앞 장의 병목에 답한다는 원칙이 첫 이음매에서 깨지고 2장이 복습처럼 보일 수 있다.
- 구체적인 수정안: 1장은 현재 성취감을 유지하고, 2장은 `왜 한 종류의 부품으로 여러 기능을 만드는가`, 보편성의 정확한 의미, 게이트 수·배선·지연의 대가를 설명하는 장으로 재정의한다. AND 합성은 1장의 결과를 인용만 한다.
- 수정하지 않을 경우의 위험: 초반부터 같은 내용을 반복한다는 인상을 준다.

### H-2. 1장에서 NAND가 충분한 동기 없이 등장한다

- 위치 또는 검토 대상: 1장 샘플의 NAND 도입부
- 문제의 내용: `이제 또 하나의 규칙을 보자`, `NAND만 주어졌다면`이라는 문장으로 NAND가 임의의 게임 규칙처럼 도입된다.
- 중요도: 높음
- 범주: 2. 일반 독자의 이해를 방해하는 설명상의 문제
- 문제가 되는 이유: 같은 진리표를 여러 방식으로 구현할 수 있다고 설명한 직후 한 종류만 사용한다는 제약의 이유가 보이지 않는다.
- 구체적인 수정안: 규칙마다 다른 부품을 만드는 대신 한 종류의 부품을 조합할 수 있다면 설계가 단순해진다는 동기 문단을 추가하고, NAND가 그 역할을 할 수 있는 이유는 2장으로 넘긴다.
- 수정하지 않을 경우의 위험: 첫 장의 인과 사슬이 `규칙 → 표 → 불명확한 제약 → NAND`가 된다.

### H-3. 6장과 7장 사이에 `명령어도 비트다`라는 연결이 없다

- 위치 또는 검토 대상: 목차 7장
- 문제의 내용: 프로그램 카운터와 명령어가 이미 존재하는 것으로 전제된다. 비트 묶음이 명령을 표현하고, 명령의 일부가 5장의 ALU 선택 신호와 레지스터 번호가 된다는 설명이 없다.
- 중요도: 높음
- 범주: 2·3. 설명 및 구조 문제
- 문제가 되는 이유: 회로에서 프로그램으로 넘어가는 핵심 다리이며, 이후 `명령 공유`의 의미를 실감하게 하는 연결이다.
- 구체적인 수정안: 7장에 4~6비트짜리 교육용 명령어 형식을 두고, 명령 비트를 ALU 선택 신호와 레지스터 번호로 해독하는 예를 추가한다. 새 장은 필요하지 않다.
- 수정하지 않을 경우의 위험: CPU가 명령어를 어떻게든 알아듣는 상자로 남고 책의 `공유` 서사가 약해진다.

### H-4. 9장에서 10장으로 넘어갈 때 SIMT 고유의 필요가 드러나지 않는다

- 위치 또는 검토 대상: 9장 다음 질문, 10장 샘플
- 문제의 내용: SIMD와 SIMT의 이익이 모두 제어·명령 비용 절감으로 설명돼 SIMT가 SIMD의 다른 이름처럼 보일 수 있다.
- 중요도: 높음
- 범주: 3. 구조 문제
- 문제가 되는 이유: SIMT가 별도 관점으로 필요한 이유에는 하드웨어 폭을 프로그램에 고정하지 않는 점, 스레드별 주소·상태, 많은 스레드를 대기시켜 메모리 지연을 다른 묶음으로 덮는 점이 있다.
- 구체적인 수정안: 9장의 닫는 질문을 `벡터 폭이 달라지거나 데이터가 기다릴 때는 어떻게 하는가`라는 병목 질문으로 바꾼다. 10장에는 폭 독립성과 지연시간 은폐의 씨앗만 심고 상세 기계장치는 11장에 둔다.
- 수정하지 않을 경우의 위험: 독자가 SIMT를 마케팅 용어로 오해한다.

### H-5. 14~15장이 메모리에서 산술 집약도로 가는 흐름을 끊는다

- 위치 또는 검토 대상: 13~16장
- 문제의 내용: 13장의 메모리 문제 뒤에 역사적 성격의 그래픽·GPGPU 두 장이 들어가고 16장에서 데이터 이동 문제를 다시 시작한다.
- 중요도: 높음
- 범주: 3. 구조 문제
- 문제가 되는 이유: 13장 메모리 계층 → 산술 집약도 → 행렬 재사용 → 타일링 → 전용화가 후반부의 척추인데 현재 배치는 이를 끊는다.
- 구체적인 수정안: 14장과 15장을 한 장으로 합쳐 12장 뒤에 놓고, `그런 대량 반복 작업이 실제로 어디에 있는가`라는 논리형 질문으로 그래픽을 도입한다. 기술사는 별도 상자로 구분한다.
- 수정하지 않을 경우의 위험: 그래픽 부분이 재미있지만 본 줄기와 무관한 우회로처럼 읽힌다.

### H-6. 19장에 신규 개념이 과도하게 몰려 있다

- 위치 또는 검토 대상: 목차 19장
- 문제의 내용: 행렬 연산의 일반 원리, 네 회사 사례, 정수·FP16·BF16·FP32, 입력·누산 형식을 한 장에서 처음 다룬다.
- 중요도: 높음
- 범주: 2·3. 설명 및 구조 문제
- 문제가 되는 이유: 세 샘플의 문체 난이도는 고르지만 목차상 실제 난이도 절벽이 19장에 예상된다.
- 구체적인 수정안: 18장과 행렬 연산 전용화 사이에 부동소수점·정밀도를 다루는 짧은 독립 장을 둔다. 범위는 수의 근사, 범위와 정밀도의 배분, FP32·FP16·BF16의 차이, 낮은 정밀도 곱셈과 높은 정밀도 누산의 이유로 제한한다.
- 수정하지 않을 경우의 위험: 낮은 정밀도가 정확도에 미치는 대가를 충분히 설명하지 못하고 후반부가 전공서로 급변한다.

### H-7. 12·19·20장에 벤더 중립 근거가 부족하다

- 위치 또는 검토 대상: 출처 관리대장
- 문제의 내용: CPU/GPU 설계 예산 비교, 행렬 전용화의 일반 원리, GPU·TPU·NPU 설계 공간을 뒷받침할 제조사 밖의 출처가 없다. 미확보 출처는 표 밖 목록에만 있어 SRC ID와 `보류` 판정이 없다.
- 중요도: 높음
- 범주: 3. 구조·차별성 문제
- 문제가 되는 이유: 벤더 문서만으로 일반 원리를 쓰면 지배적 제조사의 설명 틀을 보편 원리로 승격시킬 위험이 있다.
- 구체적인 수정안: 8·12·19·20장에 대학 교재나 학술자료를 최소 한 건씩 확보하고, 미확보 항목도 SRC-015 이후 ID를 부여해 `보류`로 표 안에서 관리한다.
- 수정하지 않을 경우의 위험: `일반 원리 뒤에 회사별 사례를 붙인다`는 원칙을 근거 체계가 뒷받침하지 못한다.

### H-8. GPU가 본격적으로 나오기 전에 분량의 45%가 지나지만 서장이 없다

- 위치 또는 검토 대상: 전체 목차
- 문제의 내용: 1·2부 목표 비중이 45%인데 GPU까지 가는 전체 지도를 먼저 보여주는 서장이나 프롤로그가 없다.
- 중요도: 높음
- 범주: 3. 구조·시장성 문제
- 문제가 되는 이유: 독자가 전반부를 GPU와 직접 연결되지 않은 논리회로·CPU 교재로 오해할 수 있다.
- 구체적인 수정안: 장 번호에 포함하지 않는 짧은 서장에서 진리표와 GPU를 같은 그림에 놓고 다섯 동사의 지도를 제시한다. 각 부 시작에서 현재 위치를 다시 표시한다.
- 수정하지 않을 경우의 위험: 차별성이 실제로 드러나는 9장 이후에 도달하기 전에 독자가 이탈할 수 있다.

## 중간 중요도 지적 요약

1. 10장 발산 예제에서 한쪽 경로가 사실상 `그대로 둔다`는 무동작이라 두 경로를 모두 실행한다는 설명이 인위적으로 보일 수 있다. 양쪽 모두 실제 연산을 하는 예로 바꾸는 편이 낫다.
2. 17장에서 말하는 이론적 재사용 횟수와 18장의 2×2 타일 모형에서 실현되는 재사용 횟수의 차이를 한 문장으로 연결해야 한다.
3. 18장에 타일링이 산술 집약도를 어떻게 높이는지 16장의 개념을 회수하는 문장이 필요하다.
4. 128→64 읽기 비교는 교육용 무캐시 기준선이며 결과 쓰기 비용은 세지 않았다는 점을 표 앞에서 더 명시해야 한다.
5. 부별 비율만 있고 장별 목표 쪽수와 도해 면적 상한이 없어 20장 구조의 실제 분량을 판단하기 어렵다.
6. 다섯 동사가 필연적인 발전 단계로 읽히지 않도록 12장 등에 `가지 않은 길` 또는 다른 설계 선택을 보여주는 절이 필요하다.
7. CUDA 문서를 13.2, 12.9.2, 버전 없는 현행 URL로 혼용한다. 문서 버전 열을 추가하고 링크와 주장을 재확인해야 한다.
8. 세 샘플 모두 도해가 없다. 목차 고정 뒤 완성 그림을 만들되 지금 도해 자리와 캡션 초안은 표시해야 분량을 계산할 수 있다.
9. 5장 ALU가 뺄셈을 포함할지 확정되지 않아 3장에서 2의 보수를 어디까지 다룰지 결정할 수 없다. Claude는 덧셈·AND·OR·NOT·뺄셈을 포함하고 3장에서 4비트 2의 보수 예를 다루는 안을 권고했다.

## 낮은 중요도 지적 요약

- 1장에 2입력 진리표가 4행, n입력이면 2ⁿ행이라는 한 문장을 넣으면 `빠짐없이`의 근거가 명확해진다.
- 절단기 안전 인터록은 실제 안전 설계보다 지나치게 단순하므로 설명용 모형이라는 각주가 필요하다.
- 10장의 `메모리 주소가 제각각이면` 문장은 실행 비용과 메모리 비용을 섞으므로 13장 예고를 붙이거나 뺄 수 있다.
- 회사별 수치는 표에 넣어도 낡는다. 이름과 역할 위주로 두고 교육적으로 필요한 숫자에만 확인 시점을 붙이는 편이 낫다.

## 샘플별 판정

### 1장 진리표·NAND: 조건부 통과

- AND·NAND 진리표와 NAND 두 개로 만든 AND의 계산은 정확하다.
- 명세와 구현의 분리, 전압·트랜지스터·지연·면적을 생략했다고 밝힌 점은 적절하다.
- 기술 오류보다 2장과의 중복, NAND 도입 동기를 먼저 해결해야 한다.

### 10장 SIMT: 조건부 통과

- warp와 wavefront를 완전히 동일시하지 않고, NVIDIA의 독립 스레드 스케줄링도 과장하지 않은 점을 정확하다고 평가했다.
- 발산 비용의 5단계, 20 레인-단계, 10 유효 레인-단계, 50% 계산은 주어진 가정 아래 맞다.
- SIMD와 다른 SIMT 고유의 동기, 양쪽 모두 실제 연산을 하는 분기 예제가 필요하다.

### 18장 행렬 타일링: 조건부 통과

- 세 샘플 중 기술적으로 가장 견고하다고 평가했다.
- 16개 원소, 8개 타일 곱셈, 타일 합과 직접 계산 결과가 모두 일치한다.
- 17장 재사용과의 연결, 산술 집약도 회수, 기준선 가정을 짧게 보완해야 한다.

### 난이도 종합

문장과 계산 예제의 난이도는 세 샘플에서 고르게 유지돼 문체상의 난이도 절벽은 없다고 보았다. 위험은 10장의 신규 용어 밀도와 19장의 개념 과부하다. 장당 신규 핵심 용어 상한을 두는 방안을 제안했다.

## 출처 체계 판정

**조건부 승인**

출처 우선순위와 각 출처의 적용 범위를 좁히는 판정 문장은 강점으로 평가했다. 반면 8·12·19·20장의 벤더 중립 근거 부족, `보류` 항목의 표 밖 관리, CUDA 문서 버전 혼재가 해결 과제로 남았다. 시장 자료는 현재 출처 표에 등록되지 않아 실제 경쟁 도서와의 차별성까지 검증할 수 없다고 밝혔다.

## 목차 고정 전에 Claude가 요구한 수정

1. 1장과 2장의 경계 재정의
2. 1장의 NAND 도입 동기 추가
3. 7장의 명령어 비트 인코딩 연결
4. 9→10장의 SIMT 도입 병목 보강
5. 그래픽 파이프라인과 GPGPU를 병합·재배치
6. 부동소수점·정밀도의 독립 장 또는 이에 준하는 독립 공간 확보
7. 장 번호에 포함하지 않는 서장 신설
8. 실제 역사와 다른 선택을 보여주는 `가지 않은 길` 장치 추가
9. ALU 연산 목록과 2의 보수 범위 확정
10. 장별 목표 쪽수와 도해 상한 작성
11. 벤더 중립 출처와 `보류` 출처의 ID 관리

Claude는 그래픽·GPGPU 병합으로 한 장을 확보해 정밀도 장에 쓰고, 필요하면 산술 집약도를 메모리 계층 후반에 흡수해 총 20장을 유지하는 안을 제안했다. 이 재배치안은 장별 학습 목표가 과밀해지지 않는지 별도 편집 판단이 필요하다.

## 최종 권고

Claude의 최종 결론은 다음과 같다.

> 재설계는 필요 없다. 정확성은 이미 확보됐으므로 세부를 늘리기보다 이음매를 정직하게 만들고, 다섯 동사가 유일한 필연적 발전 경로로 읽히지 않게 하라. 목차 고정 전 수정 목록을 처리한 뒤 샘플과 도해 단계로 넘어가라.
