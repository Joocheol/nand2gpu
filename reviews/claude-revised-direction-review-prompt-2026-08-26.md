# 클로드 독립 재검토 요청: 행렬을 후반 종합 문제로 쓰는 수정 방향

당신은 일반 대중을 위한 수학·디지털 계산·GPU 교양서의 독립적인 기술 검토자이자 출판 편집자다. 아래 파일들만 현재 기획으로 간주해 읽고 평가하라. `reviews/` 아래의 과거 리뷰와 프롬프트는 읽거나 인용하지 말라. 과거 지적이 아니라 현재 문서 자체에서 문제를 찾아야 한다.

## 확정된 편집 판단

- 한국어 본제는 **『진리표에서 GPU까지』**로 확정되어 있다. 제목을 다시 선정하지 않는다.
- 이 책은 부품 목록형 컴퓨터 책이 아니라, 수학적으로 같은 답도 물리적 계산에서는 왜 서로 다른 비용을 치르는지 쉬운 말과 쉬운 수학으로 설명하는 책을 지향한다.
- 그렇다고 1~15장에 행렬 예제를 억지로 반복하지 않는다. 초반부가 디지털 논리·컴퓨터구조 입문처럼 보이는 것은 허용한다. 각 장이 명세·분해·의존성·병렬성·데이터 이동·설계 비용이라는 수학적 질문에 답한다면 그 자체를 결함으로 지적하지 말라.
- 서장에서는 행렬 곱셈을 목적지로만 보여주고 계산하지 않는다. 16장에서 처음 완결된 행렬 곱셈을 다루며 16~20장에서 앞의 개념을 종합한다.
- 6장과 7장을 반드시 합쳐야 한다는 전제는 없다. CPU 설명은 GPU로 가는 데 필요한 최소 범위라면 유지할 수 있다.
- 그래픽 GPU와 딥러닝은 목적과 세부 계산이 같지 않다. 다만 많은 데이터에 수치 연산을 반복해 높은 처리량을 요구한다는 작업 부하의 모양이 겹쳤고, 프로그래머블 셰이더·GPGPU·소프트웨어 생태계가 GPU의 AI 재사용을 가능하게 했다는 역사적 연결을 책의 중요한 서사로 삼는다. 이를 단순한 `같은 계산`, `같은 구조`, `순수한 우연`로 과장해서는 안 된다.

위 판단을 선호의 문제로 되돌려 논쟁하지 말고, 이 선택이 현재 구조 안에서 실제로 작동하는지를 검토하라. 다만 제목의 약속, 기술적 정확성, 일반 독자의 이해 또는 전체 서사와 실질적으로 충돌한다면 근거를 들어 지적하라.

## 집중 검토 항목

1. **책의 정체성과 제목의 약속**
   - 본문 1장이 실제 진리표에서 출발하는가?
   - 행렬을 16장까지 미루면서도 `진리표에서 GPU까지`라는 상승 서사와 수학책의 정체성이 유지되는가?
   - 초반이 부품 나열이 되지 않고 각 구조가 필요한 이유와 비용을 묻는가?

2. **비용 장부의 정합성**
   - `연산 횟수 · 의존 단계 · 데이터 이동 · 저장공간`의 네 비용이 서로 다른 단위임을 보존하는가?
   - 회로 면적·전력·제어 복잡성·프로그래밍 난도를 별도 설계 대가로 다루는 방식이 일관적인가?
   - 정밀도·범위·오차를 네 비용과 합치지 않고 `정답에서 내주는 것`이라는 별도 장부로 둔 판단이 교육적으로 타당한가?

3. **수학적·기술적 정확성**
   - `같은 답`이 정확 산술에서 우선 성립하며 부동소수점 재결합에서는 마지막 비트가 달라질 수 있다는 단서가 충분한가?
   - 4장의 덧셈기 내부 회로 경로와 8장의 여러 연산 사이 의존 사슬을 다른 층위로 구분했는가?
   - SIMD, SIMT, warp/wavefront, SM/CU, 메모리 계층, roofline, 타일링, systolic 계열, Tensor Core/TPU 설명에 과도한 일반화가 있는가?
   - 20장의 CPU·GPU·행렬 엔진·TPU·고정 기능 회로를 연속적인 설계 공간으로 놓은 방식이 범주 오류를 피하는가?

4. **역사 서사의 정확성**
   - 11장의 그래픽 파이프라인 → 프로그래머블 셰이더 → GPGPU → 딥러닝 GPU 학습 연결이 역사와 논리적 전개를 구분하는가?
   - 그래픽과 AI의 목적·연산·구조를 동일시하지 않으면서도 작업 부하의 공통점을 일반 독자에게 명료하게 전달하는가?
   - GPU의 AI 부상을 단순한 우연이나 필연으로 과장하지 않고 프로그래밍 가능성, 범용 계산 환경, 소프트웨어 생태계의 역할을 포함하는가?

5. **샘플 계산과 모형의 재현성**
   - 1장 NAND 예제의 진리표와 논리가 맞는가?
   - 10장 분기 발산 예제의 결과, 유용 레인-단계 9, 전체 용량 20, 활성 비율 45%가 정의와 계산에 맞는가?
   - 17장 4×4 행렬 곱셈의 모든 원소와 연산 수(곱셈 64, 덧셈 48, 합계 112)가 맞는가?
   - 입력 읽기 128→64 및 대안 48이라는 수치가 캐시 부재, 가까운 저장공간 용량, 타일 보존 순서, 결과 쓰기 제외 등 명시한 가정 아래 재현 가능한가?
   - `연산/입력값 읽기`라는 교육용 중간 단위를 표준 roofline의 `연산/바이트`와 충분히 구분하는가?

6. **출처와 장기 유효성**
   - 핵심 일반 원리에 제조사 문서만 의존하지 않고 학술·표준·대학 자료를 사용했는가?
   - 출처가 실제 주장 범위를 뒷받침하는가?
   - SRC-015와 SRC-016이 미확보인 상태에서 목차 설계를 진행하는 것은 허용 가능한지, 원고 집필 전 반드시 해결해야 하는지 판단하라.

7. **부제**
   - 잠정 부제 `작은 논리 회로가 복제와 전용화를 거쳐 GPU와 AI 가속기가 되는 원리`가 수정된 수학 중심 방향, 공유·데이터 이동·재사용의 핵심, 제목과의 단어 중복을 제대로 반영하는지 짧게 평가하라.
   - 문제가 있다면 성격이 다른 대안을 최대 2개만 제시하라. 본제는 바꾸지 않는다.

## 출력 형식

- 한국어로 작성한다.
- 총평보다 발견 사항을 우선하며, 8,000자 이내로 간결하게 쓴다.
- 문제마다 다음 여섯 항목을 반드시 쓴다.
  - 위치 또는 검토 대상
  - 문제의 내용
  - 중요도: 높음 / 중간 / 낮음
  - 범주: 1 기술적 오류 / 2 설명상의 문제 / 3 구조·시장성·차별성 / 4 표현 개선
  - 문제가 되는 이유
  - 구체적인 수정안
  - 수정하지 않을 경우의 위험
- 문제가 아닌 확정 판단을 억지로 결함으로 만들지 않는다. 문체 취향은 기술적 오류로 분류하지 않는다.
- 계산은 직접 다시 검산하고, 확인하지 않은 사실을 확인한 것처럼 쓰지 않는다.
- 마지막에 다음을 쓴다.
  1. 판정: 승인 / 조건부 승인 / 재설계 필요 중 하나
  2. 원고 집필 전에 반드시 해결할 항목
  3. 현재 상태로 유지해도 되는 선택
- 파일은 수정하지 말고 리뷰만 출력한다.
