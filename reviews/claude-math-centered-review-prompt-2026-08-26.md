# 수학 중심 개편안 독립 리뷰 요청

당신은 일반 대중을 위한 수학·계산·GPU 교양서의 독립 기술 검토자이자 출판 편집자다. 저자의 새 방향을 지지하는 역할이 아니다. 현재 문서가 실제로 그 방향을 구현하는지 기술적 정확성, 수학적 정직성, 교육 효과, 구조적 인과관계, 시장 차별성, 장기 유효성을 기준으로 비판적으로 검토하라.

## 확정 사항과 새 방향

- 한국어 본제는 **『진리표에서 GPU까지』**로 확정되었다. 제목을 다시 선정하지 마라.
- 부제는 미확정이며 현재 작업안은 **행렬 곱셈으로 이해하는 병렬 계산과 AI 가속기의 원리**다.
- 이 책은 컴퓨터 부품을 차례로 소개하는 하드웨어 입문서가 아니라 쉬운 수학으로 계산 비용을 설명하는 교양서를 지향한다.
- 중심 질문은 다음과 같다. **수학적으로 같은 답을 내는 계산도 왜 표현·분해·순서·병렬성·데이터 이동·유한 정밀도에 따라 하드웨어에서 다른 비용을 갖는가?**
- 책 전체의 대표 계산은 행렬 곱셈이다. 다만 모든 GPU 작업과 모든 AI 계산이 행렬 곱셈이라는 주장은 하지 않는다.
- 독자는 고등학교 수준의 수학은 이해하지만 프로그래밍·논리회로·컴퓨터구조·병렬 프로그래밍을 배우지 않은 일반 독자다.
- 본문 필수 코드는 사용하지 않는다.
- 수학 서사는 `명세 → 분해 → 의존성 → 재배열 → 재사용 → 근사`다.
- 하드웨어 서사는 `조합 → 복제 → 공유 → 데이터 재사용 → 전용화`다.
- 이 흐름은 발명 역사나 유일한 필연적 진화 경로가 아니다.

## 핵심 검토 질문

1. 현재 목차는 실제로 수학책으로 읽히는가, 아니면 장 제목만 수학적으로 바꾼 컴퓨터구조 책인가?
2. 행렬 곱셈이 책 전체의 대표 계산으로 반복 회수되는가, 아니면 서장과 제4부에만 붙인 장식인가?
3. 진리표에서 행렬 곱셈까지 내려갔다 올라오는 연결은 수학적으로 정당한가? 서로 다른 추상 수준을 필연적 단계처럼 꿰맨 곳은 없는가?
4. `연산 횟수·기다림의 깊이·데이터 이동·저장공간·정밀도`라는 비용 장부는 서로 다른 단위를 억지로 나란히 놓지 않으면서 교육적으로 작동할 수 있는가?
5. 1~7장이 일반 독자에게 지나치게 긴 디지털 논리·CPU 우회로가 되지 않는가?
6. 8~15장이 work/span, SIMD, SIMT, 스케줄링, 메모리 계층, 산술 집약도를 코드 없이 쉬운 수학으로 설명할 수 있는 구성인가?
7. 16~19장의 행렬 첨자, 시그마, 블록 행렬, 부동소수점, systolic array가 한꺼번에 난이도 절벽을 만들지 않는가?
8. `같은 답`이라는 표현이 유한 정밀도 부동소수점과 계산 순서 변경에서는 거짓이 되는 문제를 충분히 통제하고 있는가?
9. 행렬 타일링 샘플의 블록 행렬 설명, 128→64 읽기 모형, 산술 집약도 설명은 수학적·기술적으로 정확하고 일반 독자에게 오해를 만들지 않는가?
10. 1장과 10장 샘플은 새 수학 중심 정체성을 실제 문체와 예제로 보여주는가?
11. GPU·TPU·NPU·ASIC을 행렬 계산의 여러 구현 답으로 비교할 때 과도한 단순화나 범주 혼동 위험은 없는가?
12. 현재 작업 부제는 일반 독자에게 책의 수학 중심성과 행렬 중심 서사를 정확히 전달하는가? 확정하지 말고 장단점만 평가하라.
13. 이 구성의 시장 차별성이 목차에서 실제로 보이는가? 확인하지 않은 판매 전망은 말하지 마라.
14. 목차를 고정하기 전에 반드시 수정할 문제와 샘플·도해 단계에서 검증할 문제를 구분하라.

## 기술 검산 요청

- 세 샘플의 모든 표와 수치 예제를 직접 검산하라.
- 행렬 타일링의 64회 곱셈, 128회와 64회 입력 읽기 모형, 2배 산술 집약도라는 결론이 명시된 가정 아래 맞는지 확인하라.
- 10장의 50% 활성 레인 모형이 결과값과 단계 가정 아래 맞는지 확인하라.
- 오류가 없다면 없다고 명시하되, 교육 모형의 가정과 실제 하드웨어 주장을 구분하라.

## 지적 형식

각 문제는 반드시 다음 형식으로 작성하라.

- 위치 또는 검토 대상
- 문제의 내용
- 중요도: 높음 / 중간 / 낮음
- 범주:
  1. 반드시 수정해야 하는 기술적 오류
  2. 일반 독자의 이해를 방해하는 설명상의 문제
  3. 책의 구조·시장성·차별성에 영향을 주는 문제
  4. 선택 가능한 표현상의 개선
- 문제가 되는 이유
- 구체적인 수정안
- 수정하지 않을 경우의 위험

기술적 오류와 편집 취향을 구분하라. 설명을 더 자세히 만드는 것이 언제나 좋은 해결책이라고 가정하지 마라. 장을 추가하자고 제안한다면 무엇을 합치거나 줄일지도 함께 제시하라.
