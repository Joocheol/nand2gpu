# Claude 독립 검토 요청: 서장·1~5장 상세 설계표

당신은 일반 대중을 위한 수학·디지털 계산·GPU 교양서의 독립적인 기술 검토자이자 출판 편집자다. 아래에 지정한 현재 파일만 읽고 평가하라. `reviews/` 아래의 과거 리뷰와 프롬프트는 이 요청 파일 외에는 읽거나 인용하지 말라. 파일은 수정하지 않는다.

## 이번 검토의 목적

목차를 다시 설계하는 검토가 아니다. 고정된 목차에 따라 만든 서장·1~5장 상세 설계표가 **도해 제작과 원고 집필을 시작할 만큼 기술적으로 정확하고 교육적으로 감당 가능한지** 판정한다.

## 확정되어 있어 재심사하지 않을 사항

- 한국어 본제는 **『진리표에서 GPU까지』**다.
- 전체는 4부 20장이다.
- 본문 1장은 실제 진리표에서 시작한다.
- 1~15장에는 행렬 예제를 반복하지 않으며, 16장에서 처음 완결된 행렬 곱셈을 계산한다.
- 서장은 `C=A×B`를 목적지로만 보여주고 행렬 계산법을 가르치지 않는다.
- 제1부는 1~5장, 총 22단위다.
- 부제는 미확정이다. 이번에 후보를 선정하지 않는다.

위 사항을 취향을 이유로 결함으로 만들지 말라. 다만 상세 설계가 이 확정 방향을 실제로 위반한다면 지적한다.

## 반드시 직접 재검산할 수치

### 1장

- AND와 NAND 진리표
- NAND 두 개로 만든 AND
- 게이트 수 2, 최장 NAND 경로 2층
- 입력 n개의 진리표가 2ⁿ행이라는 설명

### 2장

- XOR 목표 출력 `0,1,1,0`
- 방법 A의 NAND 4개와 최장 경로 3층
- 방법 B의 NAND 6개와 최장 경로 4층
- 두 방법의 모든 중간값과 최종 출력

### 3장

- 전가산기 8행
- `0101+0011=1000`
- 4비트 무부호 범위 `0~15`, 2의 보수 범위 `-8~7`
- 4비트 2의 보수에서 `0011 → 1101`, `0101+1101 → 0010`이라는 `5-3=2`
- carry-out과 signed overflow가 혼동되지 않았는지

### 4장

비교 대상은 완성 덧셈기 전체가 아니라 최종 올림 c4 회로다. 설계표의 다음 모형을 그대로 사용하되, 모형 자체가 공정한지도 비판하라.

- XOR·AND·OR는 모두 2입력, 게이트 수 1, 지연 1
- p·g는 병렬 생성
- 미리보기의 다입력 항은 2입력 균형 트리
- 곱항의 중간 결과는 공유하지 않음
- 리플: 16게이트, 최장 9층
- 펼친 c4 미리보기: 22게이트, 최장 7층
- `c4=g3 OR p3g2 OR p3p2g1 OR p3p2p1g0 OR p3p2p1p0c0`이 모든 입력에서 리플 식과 동치인지

특히 다음을 판단하라.

- 두 회로의 게이트 범위를 같은 기준으로 셌는가?
- `균형 트리`와 `중간 곱항 미공유`를 함께 가정한 22·7이 재현 가능한가?
- 일반 독자에게 이 비교가 carry-lookahead의 원리를 보여주면서도 임의적인 숫자 장난처럼 보이지 않는가?
- 더 적절한 교육 모형이 있다면 현재 안을 폐기해야 할 오류인지, 선택 가능한 개선인지 구분하라.

### 5장

- `1011₂×1101₂=10001111₂=143`
- 부분곱 `11,0,44,88`
- 4×4 곱의 한 비트 부분곱 16개, 행 4개, 네 행을 합치는 덧셈 3번, 최대 출력 폭 8비트
- 나무형 행 합의 덧셈 수 3과 의존 단계 2
- A=5, B=3인 미니 ALU의 AND=1, OR=7, ADD=8, SUB=2
- 순차 재사용을 6장의 레지스터·클럭보다 앞서 과도하게 설명하지 않는지

## 집중 교육·편집 검토

### 서장

- 행렬을 가르치지 않고도 책의 질문과 다섯 유한 조건을 구체적으로 보여주는가?
- 추상어 목록이나 GPU 홍보 문구로 끝날 위험은 없는가?
- 두 도해가 제목의 `진리표에서 GPU까지`라는 약속과 수학 중심 정체성을 실제로 전달하는가?

### 1~2장

- 1장이 디지털 부품 설명에 머물지 않고 `명세와 구현`이라는 수학적 질문으로 읽히는가?
- 1비트 AND와 0·1 곱셈표를 나란히 놓는 상자가 3장의 자릿값을 침범하지 않으면서 수학책 정체성을 보강하는가?
- 2장의 두 XOR 회로 비교가 일반 독자에게 재현 가능하며, 실제 칩 성능으로 과대 해석되지 않는가?

### 3장

- 자릿값, 반가산기, 전가산기, 4비트 덧셈, signed overflow, 2의 보수 뺄셈이 5단위 한 장에 과밀한가?
- 전가산기 8행은 표로 완결하되 산문으로 반복하지 않는 선택이 적절한가?
- 일부 내용을 보충 상자나 다음 장으로 옮겨야 한다면 정확한 위치와 남겨야 할 중심 예제를 제안하라.

### 4장

- `쉬운 말 → 생성·전파 → 식 → 게이트 모형`의 순서가 일반 독자에게 감당 가능한가?
- 4장의 한 덧셈기 내부 경로와 8장의 여러 덧셈 사이 work/span이 혼동되지 않는가?
- 게이트 수 16·22와 경로 9·7을 본문 핵심 수치로 유지할 교육적 가치가 있는가?

### 5장

- 곱셈과 ALU를 한 장에 둔 것이 `작은 함수의 조합`이라는 한 질문으로 실제 통합되는가, 아니면 두 장을 억지로 합친 것처럼 보이는가?
- 곱셈 70%, ALU 30%의 비중이 적절한가?
- 부분곱 계산이 지루한 반복이 되지 않으면서 결과와 비용을 재현하게 하는가?
- 5→6장의 `중간값을 어떻게 기억하는가`라는 연결이 자연스러운가?

### 전체 난이도와 도해

- 1비트 → 4비트 → 8비트 결과라는 상승이 과도하지 않은가?
- 장당 새 핵심어 약 5개와 도해 2개가 실제로 지켜지는가?
- 도해 명세가 장식이 아니라 게이트 수·의존 경로·명세와 구현의 관계를 검증하는 역할을 하는가?
- 일반 독자에게 반복 계산을 시키지 않는다는 원칙과 모든 예제의 완결성이 균형을 이루는가?

## 출처 검토

- 등록된 대학 강의자료와 공식 교육자료가 각 일반 원리를 충분히 뒷받침하는가?
- 상세 설계표에서 직접 유도한 교육 수치와 외부 자료에서 확인한 일반 사실이 구분되는가?
- 원고 집필 전에 반드시 추가해야 할 1차·대학 자료가 있는가? 단순히 출처 수를 늘리기 위한 제안은 하지 말라.

## 출력 형식

- 한국어로 작성한다.
- 9,000자 이내로 쓴다.
- 먼저 모든 수치의 독립 재검산 결과를 짧게 제시한다.
- 문제마다 다음 형식을 지킨다.
  - 위치 또는 검토 대상
  - 문제의 내용
  - 중요도: 높음 / 중간 / 낮음
  - 범주: 1 기술적 오류 / 2 설명상의 문제 / 3 구조·시장성·차별성 / 4 표현 개선
  - 문제가 되는 이유
  - 구체적인 수정안
  - 수정하지 않을 경우의 위험
- 문제를 만들기 위해 확정된 방향을 흔들지 않는다.
- 문체 취향을 기술적 오류로 분류하지 않는다.
- 대안이 여러 개면 장단점을 함께 제시한다.
- 마지막에 다음을 명시한다.
  1. 판정: 집필 시작 승인 / 수정 후 집필 승인 / 재설계 필요
  2. 도해 제작 시작 가능 여부: 가능 / 수정 후 가능 / 불가
  3. 원고 집필 전에 반드시 수정할 항목
  4. 초고 집필과 병행해도 되는 개선
  5. 현재 상태로 유지할 선택
- 파일을 수정하지 말고 리뷰만 출력한다.
