# Claude 8·11·16·17장 연결 샘플 독립 리뷰

- 모델·조건: Claude Opus, high effort, plan mode
- 검토 범위: 현재 프로젝트 문서 5개와 8·11·16·17장 샘플
- 제외 범위: `reviews/` 아래의 과거 리뷰와 프롬프트
- 원본 요청: [연결 샘플 검토 프롬프트](claude-connection-samples-review-prompt-2026-08-26.md)
- 판정: **조건부 승인**

## 재검산 결과

Claude는 모든 계산을 다시 수행했고 수치 오류를 발견하지 못했다.

- 8장: 합 31, 덧셈 7회, 일렬 스팬 7, 나무형 스팬 3, 최대 덧셈기 4가 맞다.
- 11장: `y=2x+10`의 여덟 결과와 곱셈 8회·덧셈 8회, `max(0,x)`의 여덟 결과가 맞다.
- 16장: 행렬의 16개 결과, 곱셈 64회, 덧셈 48회, 합계 112회, 입력 원소별 네 번의 사용이 맞다. 일렬 합 스팬 3과 나무형 합 스팬 2도 맞다.
- 17장: 8개 타일 곱과 네 결과 타일이 모두 16장 결과와 일치한다. 입력 읽기 128·64·48회와 `112÷128=0.875`, `112÷64=1.75`가 맞다.
- 48회 모형: A 타일 두 개를 유지한 채 C00을 완성해 쓴 뒤 C01을 계산하면 결과 타일 하나의 부분합 네 개만 유지해도 된다. DEC-014의 독립 정정이 옳다는 판정을 받았다.

## 원고 집필 전에 반드시 수정할 항목

### 1. 스팬 정의

- 위치 또는 검토 대상: 8장 스팬 정의, 16장 대응 설명
- 문제의 내용: 스팬을 `더 줄일 수 없는 단계 수`라고 정의하면 같은 합에 스팬 7과 3을 병기한 표와 충돌한다. 또한 덧셈기 수가 스팬을 정하는 것처럼 읽히는 문장이 있다.
- 중요도: 높음
- 범주: 2 설명상의 문제
- 문제가 되는 이유: 스팬은 선택한 계산 순서 또는 의존 그래프의 가장 긴 사슬이다. 자원 수와 같은 개념이 아니다.
- 구체적인 수정안: `이 계산 순서에서 앞선 결과를 기다려야 하는 가장 긴 사슬`로 정의한다. 일렬 순서를 택하면 덧셈기를 더 두어도 그 순서의 스팬은 그대로라고 밝힌다.
- 수정하지 않을 경우의 위험: 계산 요구량과 기계 자원을 분리한다는 책의 핵심 장부가 첫 도입부터 흔들린다.

### 2. 제3부 제목

- 위치 또는 검토 대상: 제3부 `많은 계산보다 데이터 이동이 어려울 때`
- 문제의 내용: 11장은 고정 기능과 프로그램 가능성, 12장은 계산 배치를 다루므로 현재 제목은 다섯 장 중 뒤의 세 장만 대표한다.
- 중요도: 높음
- 범주: 3 구조·시장성·차별성
- 문제가 되는 이유: 부 제목이 실제 논증을 예고하지 못한다.
- 구체적인 수정안: `많은 계산을 어디에 배치하고 데이터를 어떻게 옮길 것인가`처럼 배치와 이동의 두 축을 함께 넣는다. 부 도입에서 11~12장은 계산 배치, 13~15장은 데이터 이동이라고 밝힌다.
- 수정하지 않을 경우의 위험: 목차만 읽는 독자와 편집자가 제3부 초반을 구조적 이탈로 판단할 수 있다.

### 3. 시그마 표기 통일

- 위치 또는 검토 대상: 8장 `Σₖ₌₀⁷aₖ`, 16장 `Σₖ AᵢₖBₖⱼ`
- 문제의 내용: 8장에서 범위를 포함한 표기를 가르친 뒤 첫 회수인 16장에서 범위를 생략한다.
- 중요도: 중간
- 범주: 2 설명상의 문제
- 구체적인 수정안: 4×4 예제에서는 `Cᵢⱼ=Σₖ₌₀³AᵢₖBₖⱼ`로 적는다. 일반 크기 표기는 나중에 분리한다. 유니코드 첨자는 조판 수식으로 변환한다는 제작 메모도 남긴다.
- 수정하지 않을 경우의 위험: 8장에서 기호를 미리 도입한 교육적 효과가 첫 회수에서 약해진다.

### 4. 17장의 덧셈 48회 재현

- 위치 또는 검토 대상: 17장 블록 계산 직후
- 문제의 내용: 타일 방식에서도 덧셈 48회라고 말하지만 독자가 보이는 타일 내부 덧셈은 32회뿐이다.
- 중요도: 중간
- 범주: 2 설명상의 문제
- 구체적인 수정안: 타일 곱 8회 안의 덧셈 `4×8=32회`와 두 부분 결과 타일을 합치는 덧셈 `4×4=16회`를 더해 48회라고 밝힌다.
- 수정하지 않을 경우의 위험: 산술량은 유지되고 이동량만 줄었다는 핵심 주장을 독자가 검산할 수 없다.

### 5. 저장공간을 포함한 17장 비교표

- 위치 또는 검토 대상: 17장 방법 비교표
- 문제의 내용: 읽기 수를 결정하는 입력 저장공간과 누산 공간이 표에서 빠지고 48회 모형도 별도 행이 없다.
- 중요도: 중간
- 범주: 2 설명상의 문제
- 구체적인 수정안: `입력 슬롯`과 `누산 슬롯` 열, 48회 모형 행, `112÷48≈2.33`을 추가한다. 단, 기준선은 입력 여덟 개를 동시에 보존한다고 명시하지 않았으므로 슬롯 수를 임의로 8로 고정하지 말고 스트리밍 여부를 포함한 기준선 가정을 먼저 확정해야 한다.
- 수정하지 않을 경우의 위험: 48회가 추가 저장 자원을 지불하지 않은 무료 개선처럼 보인다.

### 6. 장말 장부 형식 통일

- 위치 또는 검토 대상: 편집 체크리스트와 네 샘플의 장말
- 문제의 내용: 체크리스트의 네 항목, 8·11·16장의 장부 표, 17장의 산문 형식이 서로 다르다.
- 중요도: 중간
- 범주: 3 구조·차별성
- 구체적인 수정안: 장부 표를 정본으로 정하고 `정확 산술에서 유지한 것 / 계산이 요구하는 양 / 기계가 제공할 자원 / 유한 정밀도에서 달라질 수 있는 것 / 설계 대가 / 남은 제약`을 기본 행으로 사용한다. 해당하지 않는 행은 생략할 수 있게 한다.
- 수정하지 않을 경우의 위험: 책의 차별점인 반복 가능한 비용 비교 형식이 장마다 갈라진다.

### 7. 11장 역사 출처 보강

- 위치 또는 검토 대상: 초기 그래픽의 고정 기능 비중, 현대 GPU의 고정 기능 경로, GPGPU 조사 논문의 연도·판본
- 문제의 내용: 현재 출처 대장은 프로그래머블 셰이더와 GPGPU 일반 흐름을 뒷받침하지만 고정 기능 파이프라인의 역사와 현대 GPU의 고정 기능 잔존을 직접 뒷받침하는 항목이 없다. Owens 조사 논문의 판본과 연도도 대장에 명시되지 않았다.
- 중요도: 중간
- 범주: 1 기술적 정확성·출처 규율
- 구체적인 수정안: 조사 논문의 판본·연도를 확정하고, 고정 기능 파이프라인 역사와 현대 GPU의 고정 기능 경로에 대한 출처를 별도 등록한다. 확정 전에는 본문 연도를 완화한다.
- 수정하지 않을 경우의 위험: 검증된 사실과 기억에 의존한 사실이 첫 역사 장에서 섞인다.

## 초고 집필과 병행할 개선

### 8. 부동소수점 차이의 범위

- 위치 또는 검토 대상: 17장, PROJECT.md, 목차 지도의 `마지막 비트·자리` 표현
- 문제의 내용: 재결합 차이를 마지막 자리로 한정하면 큰 크기 차이나 상쇄가 있는 경우의 더 큰 상대오차를 가린다.
- 중요도: 중간
- 범주: 1 기술적 정확성
- 구체적인 수정안: `대개 마지막 자리에서 갈리지만 값의 크기 차이와 상쇄에 따라 더 큰 차이가 날 수 있다`로 고친다.

### 9. 11장 작은 연표

- 위치 또는 검토 대상: 11장 역사 구간
- 문제의 내용: 2012년 외에는 시간 기준점이 없어 변화가 얼마나 오래 축적됐는지 보이지 않는다.
- 중요도: 중간
- 범주: 2 설명상의 문제
- 구체적인 수정안: 확인된 연도만 사용해 프로그래머블 셰이더 정착, GPGPU 연구 축적, CUDA 공개, 2012 AlexNet의 작은 연표를 둔다.

### 10. 16→17장의 128회 기준선

- 위치 또는 검토 대상: 16장 끝과 17장 시작
- 문제의 내용: 16장은 이론적 재사용 횟수에서 멈추고 이를 전혀 살리지 못한 기준선 128회는 17장에서 처음 나온다.
- 중요도: 중간
- 범주: 3 구조
- 구체적인 수정안: 16장 끝에 `결과마다 8개를 새로 읽으면 16×8=128회, 112÷128=0.875`를 짧게 예고하고 17장은 이를 인용한다.
- 독립 판단: 16장이 데이터 이동 장으로 팽창하지 않도록 두 줄짜리 기준선에 제한하는 것이 적절하다.

### 11. 행렬 곱셈이 성립하는 모양 조건

- 위치 또는 검토 대상: 16장 도입
- 문제의 내용: A의 열 수와 B의 행 수가 같아야 한다는 조건이 없다.
- 중요도: 낮음
- 범주: 2 설명상의 문제
- 구체적인 수정안: 예제에서는 두 길이가 모두 4라는 한 문장을 추가한다.

### 12. 17장 도입 반복 축약

- 위치 또는 검토 대상: 17장 첫 두 절
- 문제의 내용: 64회·48회를 첫 절에서 유도하고 다음 절에서 다시 인용한다.
- 중요도: 낮음
- 범주: 4 표현 개선
- 구체적인 수정안: 첫 절을 질문 중심의 짧은 도입으로 줄이고 수치 인용은 한곳으로 모은다.

### 13. 16장 16행 계산표의 배치

- 위치 또는 검토 대상: 16장 전체 원소 계산표
- 문제의 내용: 완결성과 재현성에는 기여하지만 제4부 첫 장의 흐름을 끊을 수 있다.
- 중요도: 중간
- 범주: 2 설명상의 문제
- 구체적인 수정안: 계산표를 삭제하지 않는다. 본문에는 첫 행 네 계산과 완성된 결과를 두고, 나머지 12행은 장 끝의 `검산 표` 상자로 옮긴다. `한 행×한 열`과 입력 재사용을 보여주는 도해를 본문에 둔다.
- 수정하지 않을 경우의 위험: 일반 독자가 제4부 첫 장에서 반복 산술을 건너뛰며 흐름을 놓칠 수 있다.

## 승인된 구조적 판단

- 8→9→10→11의 `합의 의존성 → 독립 계산 → 분기 → 실제 대량 계산과 프로그램 가능성` 흐름은 성립한다.
- 11장에서 행렬 계산을 16장까지 미뤄도 연결은 끊기지 않는다.
- `max(0,x)` 예제는 그래픽과 AI가 같은 계산이 아니라고 명시한 표와 후속 문단 덕분에 과대 해석 위험을 충분히 통제한다.
- `인류사적 우연`을 해석적 표현으로 제한한 문장은 정확성과 흥미를 함께 유지한다.
- 8장에서 `Σ`를 먼저 도입하고 실행 순서를 정하지 않는 명세라고 설명한 선택은 유지한다.
- 16장에서 첫 완결 행렬 계산을 하고 17장에서 원소별 계산을 반복하지 않는 선택은 유지한다.
- 16장의 16행 계산은 삭제하지 않고 위치와 시각적 형식만 바꾼다.
- 교육용 `연산/입력값 읽기`와 표준 roofline 단위의 구분은 충분하다.

## 독립 편집 판단

조건부 승인에 동의한다. 장 구성·장 수·장 순서·행렬 도입 시점을 바꿀 필요는 없다. 제3부 제목과 부 도입, 스팬 정의, 장말 장부 형식, 11장 역사 출처를 보완하면 목차를 구조적으로 고정할 수 있다.

다만 Claude가 제안한 저장공간 표의 기준선 `입력 슬롯 8`은 현재 모형에서 도출되지 않는다. 기준선은 결과 하나에 A 네 값과 B 네 값을 새로 읽는다고 했을 뿐 여덟 값을 동시에 보존한다고 하지 않았다. 쌍을 스트리밍하면 더 적은 입력 슬롯도 가능하다. 따라서 표를 추가할 때 기준선의 입력 보존 방식을 먼저 명시하거나 슬롯 수를 `미규정`으로 둬야 한다. 반면 64회 모형의 입력 8·누산 4, 48회 모형의 입력 12·누산 4는 현재 서술에서 명확히 도출된다.
