# 편집·기술 검토 기준

## 장별 필수 구성

각 장은 가능한 한 다음 질문에 답한다.

1. 이번 장의 수학적 대상은 함수, 수, 합, 벡터, 행렬 중 무엇인가?
2. 정확한 산술을 기준으로 같은 답을 내는 두 계산 방법은 무엇인가?
3. 두 방법에서 연산 횟수·의존 단계·이동·저장공간 중 무엇이 달라지는가?
4. 그 차이가 어떤 하드웨어 구조를 유리하게 만드는가?
5. 유한 정밀도를 사용한다면 정답의 범위·정밀도·오차에서 무엇을 내주는가?
6. 실제 하드웨어에는 어떤 추가 제약과 다른 선택지가 있는가?
7. 다음 장으로 넘어가게 만드는 새로운 비용이나 의존성은 무엇인가?

장 끝에는 `이번 장의 계산 장부` 표를 둔다. 기본 행은 다음과 같으며, 해당하지 않는 행만 생략할 수 있다.

- 보존한 기능·정확한 결과
- 계산이 요구하는 양
- 기계가 제공할 자원
- 유한 정밀도에서 달라질 수 있는 것
- 설계 대가
- 아직 해결되지 않은 제약

모든 장이 같은 행 이름과 순서를 사용한다. 산문으로 끝내더라도 표를 대신하지 않는다.

## 수학 중심성 점검

- 장 제목과 첫 질문이 부품 이름보다 수학적 문제를 앞세우는가?
- 하드웨어 용어를 제거해도 장의 핵심 질문이 남는가?
- 수학적 등식과 물리적 비용을 서로 다른 층으로 설명했는가?
- `이렇게 할 수밖에 없다`고 쓸 때 유한한 게이트·시간·연산기·저장공간·비트 수라는 조건을 먼저 밝혔는가?
- 하나의 구현을 수학적으로 유일하거나 역사적으로 필연적인 경로처럼 쓰지 않았는가?
- 연산 횟수, 명령어 수, 회로 깊이, 실행 시간, 데이터 이동량을 구분했는가?
- 한 덧셈 안의 회로 경로와 여러 연산 사이의 의존 사슬을 구분했는가?
- 연산 횟수·의존 단계·데이터 이동·저장공간을 서로 다른 단위 그대로 비교했으며 하나의 점수나 순위로 합산하지 않았는가?
- 계산이 요구하는 양과 기계가 제공하는 연산기 수·시간·대역폭·가까운 용량을 같은 종류의 숫자처럼 섞지 않았는가?
- 정밀도를 네 물리 비용과 같은 방향의 비용으로 다루지 않고, 정답에서 무엇을 내주는지 별도로 기록했는가?
- 회로 면적·전력·제어 복잡성·프로그래밍 난도를 빠뜨리지 않되 계산 비용과 하나의 단위로 합산하지 않았는가?
- 1~15장에 행렬 예제를 억지로 반복하지 않고 각 장에 가장 자연스러운 작은 예제를 사용했는가?
- 16장 이후 행렬 곱셈이 앞 장의 덧셈·곱셈·의존성·병렬성·재사용을 실제로 회수하는가?
- 모든 GPU 작업과 AI 계산을 행렬 곱셈으로 환원하지 않았는가?
- 정수의 정확한 연산과 유한 정밀도 부동소수점의 반올림을 구분했는가?

## 독자 이해 점검

- 새 용어는 첫 등장 시 영어 원어와 한국어 뜻을 함께 제시했는가?
- 새 부가 시작될 때 핵심 약어를 다시 풀어 썼는가?
- 수식 전에 기호와 식이 필요한 이유를 설명했는가?
- 아래 첨자와 시그마 기호는 작은 숫자 예제를 먼저 완성한 뒤 도입했는가?
- 초안의 유니코드 아래 첨자와 시그마 범위는 일반 독자도 읽을 수 있게 풀어 설명했으며, 조판 단계에서는 수식으로 통일할 항목으로 표시했는가?
- 모든 숫자 예제에 계산 과정과 답이 있는가?
- 수치 모형의 용량·재사용 범위·실행 순서·세지 않은 항목을 밝혀 독자가 같은 숫자를 재현할 수 있는가?
- 비유가 실제 구조와 다른 지점을 명시했는가?
- 설명을 위한 생략과 단순화를 밝혔는가?
- 독자에게 풀지 않은 문제나 퀴즈를 떠넘기지 않았는가?
- 한 장의 새 핵심 용어가 다섯 개 안팎을 크게 넘지 않는가?

## 기술 정확성 점검

- CPU와 GPU를 코어 수 차이로만 설명하지 않았는가?
- 지연시간, 처리량, 점유율, 대역폭을 서로 바꾸어 쓰지 않았는가?
- SIMD, SIMT, warp, wavefront의 추상 수준을 구분했는가?
- SM·CU·Tensor Core 같은 회사별 용어를 일반 개념과 구분했는가?
- 특정 세대의 실행 폭·스케줄러 수·캐시 크기를 보편적 구조로 일반화하지 않았는가?
- 이론적 최고 성능과 실제 성능을 구분했는가?
- 연산 횟수와 명령어 수를 혼동하지 않았는가?
- 연산 횟수와 계산 깊이, 데이터 이동량을 혼동하지 않았는가?
- 산술 집약도는 분자에 포함한 연산, 분모가 통과한 메모리 경계, 바이트 수, 읽기·쓰기 포함 범위를 밝혔는가?
- 행렬 곱셈의 데이터 재사용과 타일링의 관계를 설명했는가?
- 타일링 전후의 정확 산술 결과와 산술 연산 횟수는 같고 이동량이 달라진다는 점, 유한 정밀도 결과는 재결합 순서에 따라 달라질 수 있다는 점을 함께 밝혔는가?
- 정밀도, 범위, 반올림, 누산 형식의 차이를 생략하지 않았는가?
- 부동소수점에서 계산 순서가 반올림 결과를 바꿀 수 있음을 실수의 결합법칙과 구분했는가?
- GPU의 발전을 실제 역사와 논리적 구성 순서로 구분했는가?
- 특정 제품의 공개 문서가 밝히지 않은 내부 데이터 흐름을 systolic 또는 다른 계열로 추정해 단정하지 않았는가?

## 지적사항 기록 형식

- 위치 또는 검토 대상
- 문제의 내용
- 중요도: 높음 / 중간 / 낮음
- 문제가 되는 이유
- 구체적인 수정안
- 수정하지 않을 경우의 위험

각 지적은 다음 중 하나로 분류한다.

1. 반드시 수정해야 하는 기술적 오류
2. 일반 독자의 이해를 방해하는 설명상의 문제
3. 책의 구조·시장성·차별성에 영향을 주는 문제
4. 선택 가능한 표현상의 개선
